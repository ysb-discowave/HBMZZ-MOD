# HBMZZ：DFC 监控屏 + 机器控制面板 + 制式枪械 + Roblox 线圈/喷气背包

面向 **HBM 的核科技社区版（NTM:CE）** 与其 **Leafia 诅咒版附属** 的 Minecraft 1.12.2 Forge 附属模组。

放下一台 **DFC 监控屏**，它的**正面就是一台工业控制台**：开机自检、滚动 POST 日志，然后进入实时遥测。屏上的系统叫 **AHBSSMFI-OS**——环形量表、七路结构灯柱、MIMIC 结构图、带时间标尺的曲线，都是这台「设备」自己的界面语言。右键打开**可自由缩放的终端窗口**，左列是控制，右半边是这块屏的**实时预览**——预览里看到的像素，和你站在方块前看到的是同一份。

> 本项目与 NTM:CE、Leafia 官方无关，仅为社区附属。
> **部分代码来自节枝的 DFC 地图特效模组**（[DFC-Map-Creation-Tool / JiezhiMod](https://gitee.com/yi-sichen-jiezhi/DFC-Map-Creation-Tool)）：显示屏的整机 TESR 渲染、控制器 + 占位格的 12 格结构、绕顶边下倾的吊装变换、AWT 离屏画布 → 单纹理 quad 的上传管线，均取自该项目的实现。屏上显示的界面（AHBSSMFI-OS）是本项目自己的。详见文末[署名](#署名)。

## 实时屏幕

方块正面不是贴图，是一台**真在绘制的显示器**：

- **AWT 离屏画布**：全部内容用 `Graphics2D` 画到一张位图上，再作为**单个纹理**贴到一个 quad。所以同一块面板上能同时有 21px 的大号读数、10px 的中文标签、真正的圆环刻度和带抗锯齿的曲线——这是用 `FontRenderer` 在 3D 里逐字绘制做不到的。
- **3 倍超采样**：画布按 256×192 逻辑像素排版，实际纹理 768×576。4×3 的墙屏在常见视距下与屏幕像素近似 1:1，不会糊。
- **任意墙屏尺寸不变形**：面板可跨 1–4 格宽、1–3 格高（`display.defaultScreenCols/Rows`）。内容始终按 4:3 等比缩放居中，多出来的地方是黑色边框，**不会被拉伸**。整面墙只渲染一次：只有控制器格有方块实体，其余格子是无实体的占位块（`BlockDFCMonitorPart`），按构造就不可能重复绘制。
- **吊装**：贴着天花板下表面放置即为吊装——面板绕**顶边**向玩家下倾，站在下面抬头读；没有天花板则是壁挂平贴。倾角 0/15/30/45/60 五档，在终端里切换，服务端权威。
- **四个视图**（终端里切换，服务端权威）：
  - **01 核心** — 双环量表：外环是「当前温度 / 熔点」的比例并带指针与刻度，内环是稳定度；环心是整数温度，环下注明熔点。右侧是**七路结构灯柱**（STA/ABS/PLS/EMT/INJ/EXC/CMT 各一段分段灯），再往下是储能 / 输出 / 增益、崩溃风险条与熔毁预测。
  - **02 部件** — **MIMIC 结构图**：七路结构通道摆成一个环，用连线接到堆芯，装了的通道连线是琥珀色；下方是 A/B 两列燃料条与能量摘要。
  - **03 曲线** — 一张共用图：温度是填色曲线、发电量是细线，各用自己的量程；顶部是时间刻度，图底标 `-60s / now`，下方是本次会话的六项统计（最低 / 平均 / 最高 / 峰值 / 当前 / 斜率）。
  - **04 自定义** — 你自己搭的面板：显示什么、怎么排、什么时候报警，全部由「面板工坊」定义，见[下一节](#自定义面板面板工坊)。
- **开机流程**：`AHBSSMFI-OS` 启动画面（分段式进度条）→ 逐行 POST 自检 → 主界面。开机动画**只在三个时机播放**：屏幕刚被放下、存档刚被加载、以及堆芯开始坍缩（此时播的是 ERROR 301，不是开机）。其余时间面板一直停在实时主界面，不会自己重播。
- **被打掉时**：挂钩留在天花板上，一根电缆吊着整块屏掉下来，在半空中摆动，屏上切成 `NO SIGNAL` 灰雪画面，30 秒后断电消失。
- **离线与故障**：堆芯温度不到 100°C 时整屏显示「离线」，而不是满屏的 0；堆芯开始坍缩时立刻切到 **ERROR 301「与核心失去连接」**，4 秒后自动重启屏幕。
- **崩溃告警**：坍缩期间整条标题带转红、标题改成熔毁倒计时，量表与数值同步转红。
- **链路指示灯**：标题带右下、页脚跑马灯里都有 `LINK OK / LINK SLOW / 数据中断`，按最新样本的年龄变色——屏幕停住的时候，它会直接告诉你停在哪一环。
- **事件日志**：客户端比较前后两帧，只在**跨越阈值**时记一条（温度等级变化、稳定度下降、结构变化、燃料装卸、坍缩开始），不会刷屏。
- **数据推送**：服务端每 `display.displayInterval` tick 采样一次，只推给 `display.displayRange` 格内的玩家；范围内没人时连反射读取都跳过。

## 终端

- **真正可缩放**：拖右下角、滚轮、双击标题栏最大化、`复位`。上限就是**你的游戏窗口**（旧的 760×480 硬顶会让高 GUI 缩放下的窗口「拖不动」）。尺寸按方块保存在 NBT 里，且客户端本地值不会被服务端下发的方块更新覆盖。
- **左列控制 + 底部墙屏栏**：电源与四个视图（2×2 排布）加上 `面板工坊` 入口在左列；**墙屏宽 / 高 / 复位固定在窗口底边**，无论窗口拖到多小都点得到（1.5.0 里这组控件是顺序排下去的，窗口矮于约 300px 就被静默跳过，实际等于没有——这是「大小不能改」的真正原因）。
- **右侧实时预览**：跑的就是同一套画布，方块面在播开机动画时预览也在播。
- **服务端权威**：页面、电源、墙屏尺寸都发 `DFCPageMessage` / `DFCScreenMessage` 由服务端改，再广播给附近玩家，两个人同时开终端不会各改各的。
- **功率计绑定**：用「监控数据线」右键一个 NTM **功率计**（红色电缆仪表 `red_cable_gauge`），再右键监控屏即可读取每 tick / 每秒输出。
- **融毁倒计时**：
  - 坍缩阶段直接用 DFC 的 `explosionIn`（精确到秒）；
  - 稳定阶段按两颗催化剂 `damage` 的**实测增长速率**（滑动平均）推算到 100 的时间——损伤不再增长时不显示预测，而不是拿写死的速率假装在算。

## 自定义面板（面板工坊）

前三页是设备自带的仪表，第四页 **04 自定义** 是留给你的。终端左列的 `面板工坊` 打开编辑器——它是**独立窗口**，编辑的是这块屏的一份副本，只有点 `保存并应用` 才真正写进世界。

### 1. 窗口结构

| 区域 | 控件设计 | 逻辑编排 | 预设库 |
| --- | --- | --- | --- |
| **左列** | 控件库：7 类控件，点一下加到画布 | 规则列表：最多 8 条，滚轮切换 | 已保存的预设（最多 32 个） |
| **中列** | 画布：31×19 格，拖动移动、右键删除 | 选中规则的 **当 / 若 / 则** 三组积木 | 缩略预览 + 使用说明 |
| **右列** | 选中控件的属性表 | 选中积木的参数表 + 实时数据 | 命名、载入、删除、复制/粘贴 |
| **底栏** | 面板名 · 状态（`未保存`） · 还原 · 复制 · 粘贴 · **保存并应用** | 同左 | 同左 |

- 顶部三个页签 `控件设计`、`逻辑编排`、`预设库` 对应上表三列的含义。
- 画布是 **31×19 格**（1 格 = 画布上 8 个逻辑像素）。标题带 18px、页脚 179px 不参与布局，所以控件永远不会被画到边框外面。
- 网格是编辑器和方块**共用**的坐标：你在窗口里排好的位置，在 1×1 和 4×3 的屏上都按同一比例等比缩放，不重排、不拉伸。
- 控件最多 24 个，规则最多 8 条，每条规则最多 4 个条件、4 个动作——上限是刻意留低的：超出一屏的控件读不清，超出一掌之数的规则没人愿意维护。

### 2. 可添加的控件（7 种）

| 控件 | 显示什么 | 关键参数 |
| --- | --- | --- |
| **数值表** | 大字实时读数（自动缩放字号，带单位） | 通道、小数位、颜色 |
| **条形仪表** | 14 段量条 + 右上角数值 | 通道、量程最小/最大 |
| **环形仪表** | 240° 弧线表盘 + 指针 + 环心读数 | 通道、量程 |
| **状态灯** | 布尔指示灯（绿=是/红=否）+ 状态字 | 通道（布尔类）、颜色 |
| **文本标签** | 静态说明文字，自动按字符换行 | 文本内容 |
| **趋势曲线** | 该通道最近 40 次采样的折线 + 当前值 | 通道 |
| **报警横幅** | 当前报警/横幅文本；无事时显示「系统正常」 | 无（跟随报警状态） |

控件拖动时会显示落点格子，**与其他控件重叠的落点会被拒绝**；尺寸用右列的 宽度/高度 加减，同样受最小尺寸和碰撞限制。

### 3. 数据通道（条件与控件共用）

`温度` `熔点` `稳定度` `储能` `输出功率` `增益` `催化剂损伤` `结构件` `燃料A 液位` `燃料B 液位` `熔毁倒计时` `堆芯在线` `坍缩中` `燃料装入`

前 11 个是数值通道，后 3 个是布尔通道。布尔通道在做条件时不给比较符，直接给 **是 / 否**——「堆芯在线 大于 0.5」这种句子不该出现在面板上。

### 4. 搭积木：一条规则 = 当 + 若 + 则

```
当 [周期检测] 每 [20] 刻        冷却 [5] 秒    [已启用]
若 [温度] [大于] [6000]         满足全部 ▸
则 [触发报警] 等级 2 持续 10 秒
   [切换页面] → 01 核心
```

**事件积木（当）** —— 决定这条规则什么时候被看一眼：

| 事件 | 触发时机 | 适合 |
| --- | --- | --- |
| 周期检测 | 条件成立就执行，成立期间每 N 刻重复一次（电平触发）；条件不成立时每 0.5 秒复检，所以温度刚冲上去不用等满一个周期 | 「温度 > 6000 就报警」 |
| 数值穿越 | 条件由不成立变为成立的那一瞬，执行一次（边沿触发） | 「第一次超温时记一笔」 |
| 坍缩开始 | 坍缩标志 0→1 时执行一次 | 「立刻全屏报警并切回核心页」 |
| 数据中断 | 与堆芯断开（找不到堆芯）时执行一次 | 「断链通知 + 红石动作」 |
| 开机时 | 屏幕被放下、存档被加载、重新上电 | 「自检灯亮 5 秒」 |

**条件积木（若）** —— `左通道 + 比较符 + 右值`，比较符 `>` `>=` `<` `<=` `==` `!=`，右值可以是**常数**，也可以点一下切成**另一个通道**（于是能写「温度 大于 熔点」，燃料换了也不用改数字）。多条条件用 **满足全部 / 满足任意** 连接（各自对应「与」「或」），不嵌套，读一遍就能看懂。

**动作积木（则）** —— 按顺序执行，最多 4 个：

| 动作 | 效果 |
| --- | --- |
| 触发报警 | 等级 1（琥珀）/ 2（红色）+ 报警文本 + 持续秒数；持续期内每秒响一次 |
| 显示横幅 | 只出横幅、不报警（等级 0），持续秒数 |
| 蜂鸣提示 | 单纯发声，持续秒数 |
| 切换页面 | 把屏幕切到 01 核心 / 02 部件 / 03 曲线 / 04 自定义 |
| 记录事件 | 写进面板事件条（3 秒），有更高优先级的报警时不覆盖 |
| 红石输出 | 从监控屏输出 1–15 的红石强度，持续秒数后自动归零 |
| 解除报警 | 立刻清掉报警与红石，用于「温度回落即复位」 |

### 5. 触发逻辑与警报怎么生效

- **服务端权威**：规则只在服务端评估，每 **10 tick（0.5 秒）** 走一遍程序。客户端只接收结果——所以两个人看同一块屏，看到的是同一个报警。
- **每条规则独立冷却**（默认 5 秒）。没有冷却，「周期检测」会在条件成立期间每半秒触发一次，屏幕会被自己的报警刷爆。
- **周期只管重复，不管首次**：条件成立的那一遍巡检（最迟 0.5 秒后）就执行，`每 N 刻` 只用来间隔同一条规则的**重复**上报。否则一个「每 60 刻」的超温规则要等 3 秒才第一次响，操作员会以为是屏幕卡了。冷却和 N 是两把独立的锁：冷却管「刚响过别急」，N 管「还热着，多久提醒一次」。
- **边沿触发有记忆**：`数值穿越`、`坍缩开始`、`数据中断` 各记一个上次的布尔状态，只在 0→1 时触发；读档后的第一遍只记录状态、不补触发，避免一进游戏就被三条历史报警糊满。
- **报警是全屏叠加层**：报警期间，无论当前停在哪一页，标题带下方都会压一条报警条（等级 2 红色、等级 1 琥珀），四角括号闪烁。**它不是单独一页**——看着曲线图的人也必须知道堆芯超温了。
- **声音**：报警期间服务端每秒播一次（等级 2 用钟声、等级 1 用轻响）。故意不用循环音效：循环音效在区块卸载后会留下「鬼声」。
- **红石**：方块重写了 `getWeakPower` / `getStrongPower`，强度就是动作里配的数，到期自动归零并通知邻居。活塞、灯、门都按普通红石信号对待。
- **报警状态进 NBT**（等级 / 文本 / 到期世界 tick），随方块更新同步给附近玩家；到期判断用双方共享的世界时间，所以不需要额外发「报警结束」的包。
- **不存档的是运行时**：冷却、边沿记忆、红石剩余时间都只在内存里。读档后重新武装——一块关了一夜的报警屏，不该记得昨天的冷却。

### 6. 保存、编辑与复用

- **保存**：`保存并应用` 把整份设计（布局 + 程序）打成一份 NBT 发给服务端；服务端重新校验（控件数、网格边界、量程、规则条数）后写进方块实体，再 `notifyBlockUpdate` 广播给附近客户端。客户端不被信任，编辑器自己的限制只是体验，不是安全边界。
- **随存档持久化**：`panelLayout` / `panelLogic` 写在方块实体 NBT 里，拆世界、重进、区块重载都在。
- **复用 · 复制/粘贴**：底栏 `复制` 把当前设计放进会话剪贴板，打开**另一块屏**的工坊点 `粘贴` 即可，不需要先存预设。
- **复用 · 预设库**：`保存为预设` 写到 `config/hbmzz-panels.nbt`（最多 32 个命名预设）。它是**客户端资产**、与存档无关——可以发给别人，也可以带进另一个世界。载入预设后仍需 `保存并应用` 才会写进屏幕。
- **编辑**：重新打开工坊即是当前生效的设计；`还原` 丢弃本次改动回到屏幕上那一份。
- **新屏默认值**：一块新放下的监控屏自带 8 个控件（报警横幅 / 温度 / 稳定度 / 催化剂损伤 / 温度趋势 / 燃料 A、B / 堆芯在线）和 2 条示例规则（`温度 > 6000 → 报警 + 切回核心页`、`坍缩开始 → 报警`），所以第 4 页一打开就是能用的，不是空白。

## 机器控制面板

监控屏是**只读**的：它把机器在做什么念给你听。控制面板反过来——它是**能真的动手的那一块**。贴墙装一块，右键打开，转动上面的旋钮，几格外的 RBMK 控制棒就跟着进；把它接上警报器、防爆门、炮塔、流体储罐，逻辑也能自己动手。

> **归属**：这一功能的**契约、事件词表与控件集合都来自 NTM: 诅咒版**（`com.hbm.inventory.control_panel`），本模组只是把同一套 `IControllable` 协议重新实现了一遍，并换成本项目自己的扁平式面板界面。详见[署名](#署名)。

### 1. 它凭什么能操控别人的机器

诅咒版给机器定的规矩只有两条动词，本模组照抄这两条：

| 方向 | 接口 | 作用 |
| --- | --- | --- |
| 机器 → 面板 | `IControllable.getQueryData()` | 返回一张「名字 → 数值/字符串」的表，面板的读数是这张表 |
| 面板 → 机器 | `IControllable.receiveEvent(pos, ControlEvent)` | 收一条命名事件，事件里带命名变量 |
| 探测 | `IControllable.getInEvents()` | 机器自己声明它接受哪些事件名 |

- **反射，不是编译依赖**：NTM 不上任何 Maven，玩家也会自己换 NTM 版本，所以 `ctrl.MachineBridge` 用反射找接口、缓存方法句柄。找不到就降级成「面板读不到数据」并在侧栏写明原因，**不会在启动时崩**——和监控屏读取 DFC 遥测是同一套做法。
- **事件词表是抄来的，不是编的**：`rbmk_ctrl_set_level`(level)、`rbmk_crane_move`(up/down/left/right)、`tank_set_mode`(mode)、`turret_switch`(isOn)、`turret_set_target`、`siren_set_state`(isOn)、`door_toggle`、`lever_toggle`、`spinny_light_power`(isOn) 等，全部转录自 CE 2.5 的机器实现，见 `MachineBridge.KNOWN_EVENTS` 的注释。
- **没抄的部分**：CE 用的是节点图（`NodeSystem` + 一堆 `Node*` 类），连线的自由度很大，代价是站在反应堆前面的人要读一张电路图。这里换成**扁平写法**：6 个机器槽位 + 13 种控件 + 一句话规则。节点图能用两条规则表达的东西，两条规则也表达得出来，而且能念出声。

### 2. 面板结构

- **版面**：32×18 格（1 格 = 8 逻辑像素，共 256×144 的画布）。窗口里的预览和「将来贴在方块面上」用的是**同一个** `CtrlPainter`，所以编辑器里看到的就是面板上会出现的。
- **六个机器槽位 A–F**：控件和规则只指向**槽位**，从不直接存坐标。整块面板因此可以整体复制到另一台反应堆旁边，只重绑四个槽位，不用逐个控件改。
- **上限**：24 个控件、6 条联动规则。上限刻意留低——超过一屏的控件在反应堆大厅里没人读得清。
- **绑定距离 24 格**，且**只在服务端校验**：保存设计时逐个槽位重新检查「在不在 24 格内」「是不是可控机器」。不在就把这个槽位清空，但**保留指向它的控件**，重新绑上就恢复工作。

### 3. 13 种控件

分两族，因为它们的数据方向相反：**显示件**读机器，**操作件**写机器。一个控件不会两边都做——那需要两条绑定，而且「这个值到底谁说了算」会变得说不清。

| 显示件 | 显示什么 |
| --- | --- |
| 标签 | 纯文字说明，不接机器 |
| 指示灯 | 数据非 0 就亮（灯罩 + 光晕） |
| 三色指示灯 | 按数值分绿 / 琥珀 / 红 |
| 数码管 | 七段数字，适合读数 |
| 文本屏 | 字符串，或带单位的值 |
| 指针表盘 | 270° 刻度 + 指针，在量程内摆动 |
| 条图 | 横向进度条 + 右上角数值 |

| 操作件 | 怎么用 |
| --- | --- |
| 按钮 | 按下发一次事件，帽盖自己弹回（瞬时） |
| 急停按钮 | 拍下锁死并发 1，再点一次复位发 0 |
| 拨动开关 | 两态，发 0 / 1 |
| 旋钮开关 | 多档，按档位吸附后发值 |
| 旋钮 | 连续，按住左键拖，量程内取值 |
| 滑杆 | 上下推杆，量程内取值 |

### 4. 三个页签

| 页签 | 作用 |
| --- | --- |
| **运行** | 面板作为操作台。拖动旋钮 / 滑杆、单击开关与急停，机器立刻响应；下部是 A–F 六个槽位的实时状态 |
| **控件** | 控件库（13 个，点一下加到画布）、画布（拖动移动、右键删除）、右侧检查器（标签、槽位、数据键、事件、变量、量程、档位、小数、配色） |
| **联动** | 一句话规则：`当 [A] 的 [heat] 大于 [900] → 则 [B] 发 [rbmk_ctrl_set_level] 的 [level] = [0]`，含冷却与启停 |

- **选键 / 选事件**是按一下循环下一个，不弹下拉框：一台机器通常只上报三五个键，循环比在 16px 的按钮里做列表更快。
- **文本输入**只有一个编辑位：点哪个框，那个框进入输入态，画布自己画光标。`Ctrl+V` 可以粘贴（中文标签靠它），`Esc` 取消这一格，`Enter` 提交。
- **不点保存就不生效**：设计只写进窗口里的副本。`保存并应用` 才把整份设计（控件 + 槽位 + 规则）打成 NBT 发给服务端。

### 5. 绑定一台机器

1. 手持**监控数据线**右键机器 → 聊天栏提示「已记录机器坐标：RBMK 控制棒（手动）」。
2. 手持数据线右键面板 → 打开窗口；到「控件」页，A–F 某一行的 `绑定` 按钮把它接到这个槽位。
3. 点 `保存并应用`。

赶时间的话可以跳过窗口：**手持数据线潜行右键面板**，直接把它塞进第一个空槽位，并当场生效。

### 6. 操控与规则怎么生效

- **服务端权威**：每 **10 tick（0.5 秒）** 由 `CtrlEngine` 走一轮——每台机器只采样一次（`getQueryData` 是反射调用，也是这里唯一贵的地方），再刷控件、再跑规则。
- **点旋钮只发「第几个 + 多少」**：`CtrlUseMessage` 里没有事件名、没有变量名、也没有机器坐标——那些都在服务端的副本里。改过的客户端可以把 3 号旋钮拧到 60，但**不能**把 3 号旋钮改写成对任意方块发任意指令。
- **规则在服务端判**：两个人在同一块面板前看到的是同一个数、发出的是同一条命令。
- **冷却是真的会锁**：默认 5 秒，防止「温度 > 900」在区间里每半秒把控制棒按一次。
- **运行时可丢弃**：设计（控件 / 槽位 / 规则）进 NBT；运行时（当前读数、急停锁定、规则冷却）不进——一块关了一夜的面板不该记得昨天的冷却。

### 7. 已知限制

- 只有**实现了 `IControllable` 的机器**能绑；CE 2.5 里主要是 RBMK 控制棒 / 吊车控制台、防爆门、警报器、炮塔、流体储罐、电源盒、旋转警示灯这几类。
- 数据键与事件名**完全取决于机器自己的实现**：机器没上报的键，面板读出来就是 `—`；机器没公布的事件，发出去也不会有效果。

## 机器控制台（诅咒版移植版）

上一节那块**控制面板**是本项目自己设计的扁平版：6 个槽位、一句话规则、看得懂但不是原味。这一块**控制台**是另一回事——它把 NTM: 诅咒版的 `com.hbm.inventory.control_panel` **整套搬了过来**：控件、事件、变量、节点图、连线器，一个不少。诅咒版的控制台能做的，它都能做。

> **归属**：**代码全抄诅咒版**。类名、字段名、方法名、NBT 键、事件词表、控件的几何与手感都保持原样，只做了三件事：改包名到 `com.hbmzz.cecp`、降到 Java 8 语法、把 NTM 内部的渲染/网络工具类换成本项目的兼容层。界面文字改成了中文（见下文「汉化边界」）。详见[署名](#署名)。

### 1. 怎么放、怎么开

| 操作 | 结果 |
|---|---|
| 放下方块 | 底边吸附在你点的那一面；对着**天花板**放是吊装（板面朝下），对着**地板**放是平台式，对着**墙**放是贴墙式 |
| **手持螺丝刀**右键 | 打开布局编辑器（和诅咒版一致：NTM：诅咒版的「螺丝刀」「Desh 螺丝刀」都认，按注册名匹配，装了 NTM 就直接用；主手副手都行） |
| **手持监控数据线**右键 | 同上，打开布局编辑器（没装 NTM 时的替代工具，本模组自带的） |
| **空手**右键板面上的某个控件 | 按下它：发一条 `ctrl_press` 给这个控件自己的节点图 |
| 给它旁边的方块供电 | 红石值进入面板的 `redstone_input` 节点 |
| 手持方块右键 | 正常放置方块（不会被面板吃掉右键） |

方块会**输出红石**：面板上任何一个 `redstone_output` 节点算出来的值，就是这个方块的**弱/强充能强度**，六面都算。所以一个控制台可以直接拿来当可编程的红石控制器。

### 2. 三层结构：控件 → 事件 → 节点图

诅咒版的设计是「每个控件带一张自己的电路图」，这三层必须一起看才明白：

```
物理控件（按钮/旋钮/表盘…）        ← TESR 画的立体模型，右键能按
  └─ vars     几个有名字的值        ← isPushed / isOn / value / color…
  └─ 接收事件  ctrl_press / tick    ← 机器或玩家发进来
  └─ 发送事件  set_redstone / …     ← 图里能发出去
  └─ 节点图    NodeSystem           ← 一个事件一张图，图里的节点算完写回 vars
```

- **控件自己就是一台小机器**：它不直接连反应堆。按钮被按下，只是把 `isPushed` 从 0 变成 1，然后跑一遍绑定在 `ctrl_press` 上的节点图。
- **真正动手的是节点图**：图里放一个 `红石输出` 节点，它写的是**控制台方块**的红石；放一个 `广播事件` 节点，它把事件发给**同一张面板上的别的控件**；放一个 `查询方块` 节点，它去问附近方块要数据。
- **所以「做一台能开防爆门的控制台」= 放一个按钮 + 给按钮的 `ctrl_press` 图加一条到红石输出的线**，不用写规则表。

### 4. 节点图里有什么

| 分类 | 节点 |
|---|---|
| 输入 | 事件数据、读取变量、查询方块、红石输入、批量查询、图表区间 |
| 输出 | 广播事件、取消当前事件、设置变量、红石输出、播放声音、写入图表 |
| 数学 | 加减乘除、取余、幂、对数、指数、平方根、绝对值、比较、限幅、最大最小、取整（20 种运算，一个节点切着用） |
| 布尔 | AND / OR / NOT / XOR / NAND / NOR / XNOR，外加脉冲、SR 锁存 |
| 逻辑 | 函数（自定义表达式）、缓冲器（延迟一拍）、条件（if） |
| 数据包 | 读取数据包、写入数据包（复合类型打包/拆包） |
| 文本 | 文本拼接、取子串、格式化、数值缩写 |
| 实用 | 缓存、时钟、随机整数、随机小数、汇总、文本转数字 |

- **函数节点**用诅咒版的表达式解析器，可以写 `a*2+sin(b)` 这样的式子。
- **变量**分**局部**（只在这个控件里）与**全局**（整张面板共享）两栏，`读取变量` / `设置变量` 都带全局/局部下拉。
- **红石输入**能选六个面 + 六种读法（强度、弱充能值、强充能值、是否通电、是否弱充能、是否强充能）。
- **红石输出**能选六个面 + 弱/强充能。
- **事件表不是抄死的**：节点下拉里的事件直接镜像 CE 自己的注册表（`com.hbm.inventory.control_panel.ControlEvent` 的 `REGISTRY`），而不是本项目抄一份名单。所以装了 CE 附属（CE Addon / Leafia 往同一张表里追加了 `set_booster_level`、`pwr_ctrl_set_level`、`set_pump_pressure` 等 17 个事件）时，这些事件在广播节点上一样带自己的变量，不会退化成只剩一个 `Cancel`；事件数据节点也照样能读出它们的值。见 `compat/CEEventTable`。
- **投递不看本项目的注册表**：广播节点把事件交给 `ControlEventSystem`，而这张表里只有控制台自己（它只登记 `tick`），CE 的机器一台都不在里面。所以目标位置先在本表里查，查不到就走 `compat/CPMachines`——把 CE 机器包成 `IControllable`，由 `ctrl/MachineBridge` 反射发出**上游自己的** `ControlEvent`。`tools/linkercheck` 里有一条 `broadcast visits every linked position` 的检查专门盯这个：早先的版本在这张空表上直接 `return`，一个位置都不访问，界面上看不出任何异常。
- **文本 / 实用 / 布尔扩展 / 播放声音来自 CE Addon（Leafia）**：这十四个节点不在 CE 本体里，是附属模组注册进同一张节点表的。名单与 `nodeType` 字符串照抄，所以装了附属的面板存档能原样读进来；`NodeSnd` 里的音效按类名反射解析，没装附属就自动从下拉里消失而不是崩。见 `nodes/addon/` 与 `modular/AddonNodeLoader`。
  - `批量查询` 是本项目对上游的一处修正：上游用 `tile instanceof IControllable` 找机器，只能看见自己模组的机器；这里改走 `CPMachines`，所以 CE 的 RBMK 棒也算得进去。
  - `播放声音` 返回 `true` 而不是上游的 `false`——在广播链路里 `false` 的意思是「取消这个接收者」，一个音效不该把整条事件吃掉。

### 5. 编辑器有哪几页

| 页面 | 干什么 |

| 节点分类与菜单项 | 事件词表（`ctrl_press`、`initialize`、`tick`…） |
| 按钮标题（`返回` / `完成` / `清空` / `建立连接`…） | 控件变量名（`value`、`isOn`、`isLit`…） |
| 滑条与提示文字（`高度 ` / `角度 ` / `位数 ` / `Shift+A 添加节点`） | 六个方向名（`north` / `south`…）——它们同时是匹配键 |
| 数学/布尔运算的显示名 | 数据包字段名 |

理由很简单：**左边那列改了不影响任何逻辑，右边那列是协议**。事件词表是机器那边认的字符串，变量名要跟 `IControllable.getQueryData()` 返回的键对上，NBT 键是存档格式——翻哪一个都会让面板读不到数、发不出事件、或者读不了旧存档。

#### 节点图里的中文（2.1.6 修）

汉化到这里踩了一个坑：诅咒版在画节点图之前会执行 `fontRenderer.setUnicodeFlag(false)`，因为它图里**全是英文**，ASCII 字模在小字号下更清楚。中文落到这个模式里会被 `FontRenderer` 按 `ch % 256` 砍成 ASCII 字模，于是节点标题、下拉项、参数标签全变成方块和问号，宽度也算错——看起来就是「积木参数显示不齐」。

现在节点图整段保持 unicode 字模开启，并且**所有小字号标签改成按实测宽度裁剪**（`com.hbmzz.cecp.compat.CPFont` 的 `clip` / `cut`）。诅咒版原来的写法是硬截 5 个字符，对 ASCII 是 30 个单位、对中文是 45 个单位，四五个汉字就会顶到端口标签上；改成量宽度后，中英文都不会越界：

| 位置 | 可用宽度（未缩放单位） |
|---|---|
| 节点标题 | 36（框宽 40，从 +4 起） |
| 参数名 | 44 |
| 参数值 | 30（右对齐到 +94） |
| 输入端口默认值 | 40 |

同时修了画布的裁剪框：`glScissor` 的原点在左下角，诅咒版直接把左上角坐标喂了进去，等于把可见区整体下移了 36 个单位，画布顶部（含那行 `Shift+A 添加节点` 提示）会被切掉。现在按真实帧缓冲高度翻转。

### 7. 与「机器控制面板」怎么选

| | 机器控制面板（本项目设计） | 机器控制台（诅咒版移植） |
|---|---|---|
| 界面 | 窗口里的 2D 画布 | 世界里的立体面板 + 窗口编辑器 |
| 逻辑 | 6 槽位 + 一句话规则 | 每个控件一张节点图，可互相广播事件 |
| 控件 | 13 种，AWT 绘制 | 14 种，OBJ 立体模型 |
| 多机联动 | 有（槽位表） | 有（连接器 + 查询方块节点） |
| 上手成本 | 低，规则表就是全部 | 高，但表达力是图灵完备级别的 |
| 代码来源 | 契约抄 CE，实现自写 | **整套抄 CE**，只做兼容层与汉化 |

两块可以同时装、互不干扰，各用自己的界面。

### 8. 已知限制

- **OpenComputers 集成去掉了**：诅咒版的控制台能接 OC 的组件总线，本模组不带 OC 依赖，这部分代码没有移植。
- **渲染走的是兼容层**：诅咒版用 NTM 自己的 `NTMBufferBuilder` / `NTMImmediate` / `VAO`，这里换成本项目的 `CtrlBuf` / `CtrlImm` / `ObjModel`（`com.hbmzz.cecp.compat`）。模型文件与 UV 完全一样，画出来的东西应该一致；性能上比 VAO 差一点，一块面板的顶点量无所谓。
- **只有实现了 `IControllable` 的方块能被连接**。CE 里那些机器在**自己的包**里实现了同名接口（`com.hbm.inventory.control_panel.IControllable`），跟本模组的 `com.hbmzz.cecp.IControllable` 是两个类型——2.1.5 起中间的 `BridgedControllable` 把 CE 机器包一层再交给面板，所以两边都能接；判断仍是反射，机器不见了只会在导入结果里报「非可控」，不会崩。
- **从机器发给面板的事件（机器 → 面板方向）暂时收不到**：CE 的机器只往 CE 自己的事件总线广播，本模组的面板不在那条总线上。面板 → 机器是通的（见下一节）。
- **节点图的存档与 CE 不通用**：方块不同、注册名不同，本模组的面板只在 `hbmzz` 的方块实体里存。

### 9. 上游有、本版没有的控件怎么办

先说结论：**截至 2.1.7，一个都没缺。** 从整合包里 `NTM-CE-1.12.2-2.5.0.5.jar` 扒出 `com/hbm/inventory/control_panel` 的 83 个类（94 个 class 文件含内部类），与本模组 `com/hbmzz/cecp` 逐文件比对，差集为空；控件注册表 14 项（`button_push` … `label`）、节点菜单 6 类 15 项（`cancelEvent` / `eventBroadcast` / `getVar` / `queryBlock` / `redstoneInput` / `math` / `boolean` / `function` / `buffer` / `conditional` / `setVar` / `redstoneOutput` / `input` / `composite_read` / `composite_write`）与 `StockNodeLoader` 的 switch 分支一一对应。所以如果你手上有一块面板是「在原版里有、拿过来不见了」，那不是漏移植，而是下面三种情况之一。

这条结论现在可以自己复核：

```bash
# 1. 类覆盖与方法覆盖
./tools/parity/run.sh "/c/.../mods/[HBM的核科技社区版] NTM-CE-1.12.2-2.5.0.5.jar"
```

输出 `ported classes: 83/83`。

```bash
# 2. 逐文件 token 级比对（两边都反编译，格式差异全部消失）
python tools/parity/decompiled_diff.py "/c/.../NTM-CE-1.12.2-2.5.0.5.jar" \
    --java "C:/Program Files/Java/jdk-25.0.4/bin/java"
```

第二个脚本更严格：上游的 class 与本模组编译出来的 class **各自**过一遍同一个反编译器，再逐行去掉空白后比 token。这样「同一个方法换了个折行方式」「`this.` 有无」「`<>` 推断」这些噪声全部消失，剩下的才是真的逻辑差异。2.1.7 的结果是 **12 个文件 token 级完全一致**，其余 71 个的差异逐条看下来只有三类：

| 类别 | 例子 | 为什么 |
|---|---|---|
| 汉化字符串 | `"Back"` → `"返回"` | 只在 `getDisplayName()` / 按钮标题 / 下拉项，不参与比较与存档 |
| 兼容层 | `NTMRenderHelper` → `GuiFx`、`ResourceManager.white` → `CtrlRes.white`、`hbm:` → `hbmzz:` | 上游那套渲染器/资源管理器不在本模组里 |
| jvmdg 垫片 | `J_U_SequencedCollection.addFirst(x, y)` ↔ `x.addFirst(y)` | 同一字节码，上游为兼容 JDK8 生成了垫片调用 |

唯一需要留意的一条规则，也是这轮踩到的：**协议字符串不能翻**。`NodeInput` 的 `name` 既是标题又参与 `NodeSystem.canPasteFromNBT` 的比较、还要写进 NBT，所以它保持 `"Event Data"`，只在 `getDisplayName()` 里翻成「事件数据」。

**情况一：存档里的控件名本版不认识。** 比如从 CE 的存档转换过来，或者在旧版本里放过后来被删掉的控件。这种情况**数据不会丢**：`ControlPanel.readControl()` 认不出名字时不会跳过，而是建一个 `UnknownControl` 把原始 NBT 整个扣下来（`rawTag`），`writeToNBT` 时原样写回。2.1.3 起它在面板上画成**洋红色带黑框的占位块**（之前 `render()` 是空的，所以是"凭空消失"），在编辑器里也会显示控件名。等你把对应的控件类补回来，同一块面板下次加载就自动还原，不需要重新摆。

**情况二：它本来就是「纯显示」控件。** 圆形仪表、方形仪表、七段数码、文字屏、指示灯、RGB 灯、标签这 7 种的 `getBoundingBox()` 返回 `null`——在原版里也只能看不能按，只有按钮 / 急停 / 防护按钮 / 拨动开关 / 旋转开关 / 滑条 / 旋钮这 7 种能被右键按下。这不是缺失。

**情况三：节点图里出现了灰/洋红色的「未知节点」。** 同理，`NodeSystem.readFromNBT` 遇到不认识的 `nodeType` 会塞一个 `UnknownNode`，连线（`in`/`out`）保留，求值时按类型返回 `ERROR` / `NaN`，不会让整张图崩掉。

如果你确实想补一个上游后来才加的控件或节点，改三处即可：

**加控件**（以「自锁按钮」`ButtonLatching` 为例）

1. 写类：`com/hbmzz/cecp/controls/ButtonLatching.java`，`extends Control`，实现 `getControlType()` / `getSize()` / `getModel()` / `getGuiTexture()` / `newControl()`。模型与贴图丢到 `assets/hbmzz/models/control_panel/` 与 `.../textures/models/control_panel/`（没模型就复用现成的 `button_push.obj`，`getModel()` 返回 `CtrlRes.ctrl_button_push`）。
2. 注册：`ControlRegistry.init()` 里加一行 `registry.put("button_latching", new ButtonLatching("自锁按钮", "button_latching", null));`。**第一个参数（key）与第二个参数（registryName）必须一致**，否则存进去读不回来——这是唯一容易踩的坑。
3. 需要默认变量就在构造函数里 `vars.put(...)`，事件用 `populateDefaultNodes()` 塞进节点图。

**加节点**

1. 写类：`com/hbmzz/cecp/nodes/NodeXxx.java`，`extends Node`，至少实现 `evaluate(int idx)`、`getColor()`、`getDisplayName()`、`writeToNBT` / `readFromNBT`（`nodeType` 字符串自己定，但要和加载器对上）。
2. 加载：`modular/StockNodeLoader.java` 的 switch 加 `case "xxx": node = new NodeXxx(0, 0); break;`。**漏这一步的表现就是节点放得下、存得住，但重开世界后变成「未知节点」**。
3. 菜单：在对应的 `modular/categories/NCStock*.java` 里，`addItems` 加一行显示名、`newItem` 里按索引 `return new NodeXxx(x, y);`（索引顺序必须和 `addItems` 一一对应，错位会让你点「条件判断」放出来「缓冲器」）。

### 10. 怎么把机器接进面板（2.1.5）

这是整块面板唯一的入口，之前坏了三轮都是它：

1. **记录坐标**：手持 **监控数据线**（或 NTM 的 **多发起爆器**，两个都认）右键机器。能接面板的机器会回一句「已记录机器坐标：<机器名>」；不能接的也会记录，并说明「这个方块不受控制面板控制」——以前这种情况什么都不说，看起来就像没反应。
2. **导入**：打开控制台的「建立连接」页，把线/起爆器放进左上角槽位，按 `>`。界面顶部会直接写出结果：`导入 N 台（新增 a，重复 d），忽略 r 个非可控坐标`。
3. **继续**：按「继续」进事件页。这时两台列表（可接收事件 / 可发送事件）才有内容——**它们是从已连接的机器身上取的事件名**，没有机器就是空的；节点图里「查询方块」的数据下拉、「广播事件」的事件下拉同理。

因此「某些积木好像不存在」通常不是节点没移植，而是**没有连机器**：`广播事件` 的下拉来自 `getInEvents()`，`查询方块` 的下拉来自 `getQueryData()`，两者都由已连接的机器提供。

CE 的机器在 `com.hbm.inventory.control_panel.IControllable` 上声明同样的三个动词，本模组通过 `com.hbmzz.cecp.compat.BridgedControllable` 包一层接进来；`CPMachines.at(world, pos)` 是唯一入口，链接页、查询节点、事件派发都走它。

**多方块机器（2.1.7）**：RBMK、炮塔这类大型机器在世界里是一堆 `BlockDummyable` 填充方块 + 一个 `TileEntityDummy` 指向真正的方块实体。直接把「记录的坐标」拿去 `getTileEntity()`，拿到的只是个占位方块实体，三个控制动词一个都没有——上游的链接页因此专门做了三层解析，本版一开始漏了这一步，表现就是**多格机器怎么点都导不进来**。现在 `CPMachines.coreOf()` 按上游同样的顺序走：

```
点到的那一格 → BlockDummyable.findCore(world, x, y, z) → 核心坐标
             → 若核心上是 TileEntityDummy → 取它的 target
```

所以点机器**任何一格**都能导入，列表里显示的坐标就是最终存进去的核心坐标。这两步都是反射（`findCore(IBlockAccess, int, int, int)` 与 `TileEntityDummy.target`），类不在就整段跳过，退化回「按原坐标查」，不会崩。

已验证的机器（CE 2.5 里实现该接口的全部 10 个）：门、防爆闸门、警报器、流体储罐、电源盒、旋转警示灯、RBMK 通道及其子类（控制棒 / 蒸汽发生器 / 吊车控制台）、炮塔、控制面板。

## 视频广播器

一块占满整格的机器：**红石上升沿一到，被选中的玩家屏幕上没有任何过渡——画面直接黑掉，然后开始播一段视频**，播完自动恢复。

### 1. 红石触发逻辑

- **只认上升沿**。拉杆一直按着是一次广播，不是每秒二十次；从"没电"到"有电"的那一刻才发。
- **第一个 tick 不算触发**。方块实体建出来（进存档、区块重载）时先把当前电平记下来但不发信号——站在红石块旁边上线，不该被自己的机器糊一脸。
- **按 tick 轮询，而不是听邻居通知**。红石本来就是按 tick 结算的，`isBlockPowered` 每 tick 问一次与任何 `neighborChanged` 钩子一样快，但**不会漏**：区块重载后回到一根通电的红石线旁边，是收不到那个"变化"的。而这里漏一次的后果是屏幕永远不接管，属于这台机器唯一赔不起的 bug。
- **冷却**：两次广播至少隔 `video.cooldownTicks`（默认 20 tick = 1 秒），更快的高频时钟（漏斗钟、中继器环）被忽略并写进状态行，免得视频变成频闪。
- 方块正面的小灯跟着红石亮，纯装饰。

### 2. 全屏占用与播放

客户端收到一个二十来字节的包，然后：

| 阶段 | 发生什么 |
| --- | --- |
| 接管 | `displayGuiScreen(new GuiVideoScreen(...))` —— 一个铺满整个窗口的不透明四边形。HUD、物品栏、聊天、世界全在它下面。没有渲染钩子，没有覆盖层。 |
| 黑屏 | 第一帧解出来之前是纯黑，通常 50–150 ms。读起来像显示器在切输入源，而不像卡死。 |
| 播放 | 按**时钟**走，不按帧计数：`帧号 = 已过秒数 × fps`。机器跟不上就丢帧，声音不会跑偏——视频里晚到的帧比没有的帧更难看。 |
| 结束 | 自动关闭，回到游戏。 |

- **ESC 默认无效**，其它按键也一律吞掉，鼠标点击不会漏到身后的世界。这是刻意的：能一个键关掉的接管不叫接管。配置里 `video.allowEsc=true` 可以恢复。
- 画面**等比缩放 + 上下黑边**，不拉伸。
- 音频是可选的 `audio.wav`，走 JRE 自带的 mixer。没有声卡、格式不认、混音器被占，都只是静音播放，不会拦住视频。

### 3. 右键配置界面

一块 320×200 的窗口，两个输入框：

- **视频文件** —— 输入名字，或者从下面的清单里点一个；清单只列 `config/hbmzz/videos/` 里真的有的东西。
- **广播目标** —— **就是命令方块那套选择器**：`@a`、`@p`、`@r`、`@a[r=32]`、`@a[x=..,dx=..]`、`@a[team=red]`、`@p[score_x_min=10]`……不是仿写的方言，是原版 `EntitySelector` 在解析。

输入框下面那行实时说两件事：本机有没有这个视频、选择器此刻匹配到几个人。它是**预览**——多人客户端解析不了裸 `@a`（那需要服务端的世界列表），这时它会直说"只能在服务端解析"，不猜。

三个按钮：`保存并应用`、`测试广播`、`关闭`。测试走的是**和红石完全相同的那条路**；保存**不会**触发——顺手把人家屏幕黑了不是好设计。

### 4. 数据存储结构

方块实体里就两个字符串，跟存档走：

| NBT 键 | 内容 |
| --- | --- |
| `video` | 视频包名，如 `alarm` |
| `selector` | 选择器原文，如 `@a[r=32]` |
| `status` | 服务端最后一句结果；**只走同步包，不存档**——重进世界不该复活上周那句"没有匹配到玩家" |

服务端权威：窗口只编辑一份工作副本，按保存才发 `VideoConfigMessage`，服务端**重新校验**一遍——名字白名单、选择器长度、距离、可选的管理员门槛。编辑器的检查是方便，不是边界；因为这两个字段最后会变成"强制替换某个玩家屏幕"的命令。

### 5. 视频文件怎么加载

`config/hbmzz/videos/`，两种形状都认：

```
alarm.zip            alarm/
  meta.json            meta.json
  f000001.jpg          f000001.jpg
  f000002.jpg          f000002.jpg
  audio.wav            audio.wav
```

`meta.json` 可以整个省掉：缺省 12 fps，帧数按目录里实际有几张图算；声明了帧数却少文件，就以少的那个为准（不然播放器会等一堆永远不来的帧）。每帧在**解码线程**上重画成固定尺寸的 `TYPE_INT_RGB`，贴图因此只分配一次，之后是单次子图上传。

一条命令把 mp4 打成包：

```bash
python tools/video/pack.py alarm.mp4 alarm --fps 12
```

**为什么不是 mp4 文件本身**：1.12.2 的客户端只有一个 JRE，没有 H.264 解码器；塞原生解码库意味着每个平台各带一份二进制。帧序列 + `javax.imageio` 什么平台都能解，代价是体积——所以帧会按 `video.maxWidth`×`maxHeight` 缩小，解码线程只保留 `video.cacheFrames` 帧的窗口（默认 6），不会把整段视频读进内存。

**文件在客户端，不在服务端**。服务端只发"播 alarm"这几个字，跟材质包是同一个交易：网络上传不动的东西就不传（30 秒 480p 是几十 MB）。所以：

> 视频要放到**每一台需要观看的客户端**的 `config/hbmzz/videos/` 下。客户端没有这个文件时，它不会给你一块沉默的黑屏，而是直接报出缺的文件名和它找过的路径。

名字是**白名单不是路径**：`[A-Za-z0-9][A-Za-z0-9_.-]{0,63}`，不含分隔符、不含 `..`，服务端和客户端各校验一次。否则一个恶意服务器就能让客户端去打开 `../../options.txt`。

### 6. 目标玩家怎么匹配

- 选择器交给原版 `EntitySelector`，方块**扮成命令发送者**（命令等级 2，与命令方块同权）。
- 半径和坐标以**方块**为原点，不是玩家——这样 `@a[r=32]`、`@a[x=..,dx=..]` 才有意义。
- `@s` 会失败：它表示"执行这条命令的实体"，方块不是实体。**不会**被偷偷降级成 `@p`——服务器上旁边站着两个人的时候，那就广播到别人屏幕上了。
- 不以 `@` 开头的输入按**玩家名**处理（原版命令方块只认发送者自己，这里放宽一点，因为往框里打 `Steve` 应该能用）。
- 匹配不到人、选择器写错，都只得到一句人话，不会触发任何东西。

## HUD
准星指向 16 格内的监控屏时，左上角淡入一块迷你面板（温度/储能/稳定度 + 状态），松手淡出；`F1` 隐藏界面时不显示。

## 方块与物品

- **DFC 监控屏**：吊装式工业终端。方块本身**不渲染**（`INVISIBLE` + 空模型），整台设备由
  TESR 画：半厚 0.075 格的外壳、宽 0.10 格的前框（四角螺栓 + 底部状态灯）、边框内侧的阴影缝，
  玻璃贴在前框后面 3 毫米。顶边有天花板吊架：夹钳咬住面板上沿，两端各一个铰链座，
  两根吊柱向上插进天花板，末端是一块法兰板。
  贴着天花板放置即为吊装：面板绕**顶边**下倾，站在下面抬头正好读；没有天花板则为壁挂、平贴。
  倾角在终端窗口里切换，0~60 度五档；整体前进量恒等于面板中心被推开的那点距离，
  所以无论多陡，屏都不会离开自己占的那几格。
- **屏幕占位格**：面板除控制器外的格子，没有方块实体，只提供碰撞与"拆一格带走整屏"的入口。
- **机器控制面板**：3/16 格厚的贴墙铁板，正面是屏幕 + 三色灯 + 旋钮与拨杆的贴图。**没有 TESR**——一块 16×16 的板子从两格外就看不清字了，老实给个方块模型，真正的面板放进右键打开的窗口里。
- **机器控制台**：诅咒版控制台的整体移植。方块本体**不渲染**（`ENTITYBLOCK_ANIMATED` + 空模型），整块板子连着上面装的所有控件由 TESR 画出来——所以控件是**真立体模型**，会随斜面一起转。
- **监控数据线**：一个物品干两件事——记录 DFC 核心/功率计并绑定到监控屏；记录可控机器，并当控制台的**配置工具**用。

## 使用

1. 放下监控屏，正面会自己开机并显示读数（需要 16 格内有核心，或用数据线绑定）。
2. 没有绑定核心时，终端会在 16 格半径内自动搜索 `TileEntityCore`。
3. 想固定核心或读取功率计：手持监控数据线右键 DFC 核心 / 功率计，再右键监控屏。
4. 右键监控屏打开终端：
   - 左侧 `已开机 / 已关机` 切换屏幕电源；
   - 用 `1 核心遥测 / 2 部件监视 / 3 曲线记录` 换页；
   - `宽度 / 高度` 的 `−` `+` 调整墙屏跨几格；
   - 拖右下角、滚轮或双击标题栏调整**终端窗口**大小。
5. 屏幕上的读数：
   - `温度` — 当前温度、熔点、每秒升温；
   - `稳定度` — 稳定器总和的归一化百分比（满标 10）；
   - `能量` — 储能 / 输出 / 势能增益，单位 SPK；
   - `崩溃` — 催化剂损伤进度（DFC 只把坍缩暴露成布尔值，所以表盘由可预测的损伤度驱动）；
   - `事件日志` — 最近 12 条，按阈值跨越记录。
6. 想**操控**机器而不是只看：放一块机器控制面板，用监控数据线右键机器记录、再右键面板开窗，在 A–F 里绑定、摆好控件、`保存并应用`，然后切到 `运行` 页拧旋钮。见[机器控制面板](#机器控制面板)。

## 工作原理

| 类 | 职责 |
| --- | --- |
| `dfc.DFCReader` | 反射读取 NTM/诅咒版核心与功率计，全部空值保护 |
| `tile.TileEntityDFCMonitor` | 保存绑定/尺寸/页面/电源；服务端定时采样并推送；客户端保存样本与升温趋势 |
| `client.screen.DfcScreen` | **AWT 离屏画布**：全部页面、开机动画、301 页、事件日志、纹理上传 |
| `client.screen.ScreenFonts` | 字体探测（Consolas / 微软雅黑），中文与等宽分族 |
| `client.screen.DfcFormat` | 数值口径：SPK、稳定度归一、等级阈值、倒计时 |
| `client.RenderDFCMonitor` | 把 `ConsoleModel` 的四边形交给 tessellator，贴玻璃纹理；纹理生命周期 |
| `client.ConsoleModel` | **整台设备的几何**（吊架/外壳/前框/螺栓/状态灯），不碰 OpenGL，可离线出图 |
| `dfc.ConsoleRig` | 倾角档位、前进量、渲染锚点、多方块占位，全部纯函数 |
| `block.BlockDFCMonitorPart` | 屏幕的占位格：**没有方块实体**，所以整块屏只渲染一次 |
| `client.screen.TerminalCanvas` | 终端窗口的 AWT 画布与点击热区 |
| `client.GuiDFCMonitor` | 窗口缩放/拖拽/滚轮、控件分发、预览贴图 |
| `ctrl.MachineBridge` | **反射桥**：NTM 诅咒版 `IControllable` 的两个动词 + 事件词表 + 中文机器名 |
| `ctrl.CtrlEngine` | 服务端每 10 tick 的一轮：采样 → 刷控件 → 跑规则 → 派发事件 |
| `ctrl.CtrlPanel` / `CtrlWidget` / `CtrlRule` / `CtrlLink` | 面板设计模型（32×18 格、13 种控件、6 槽位、6 条规则）与 NBT |
| `tile.TileEntityCtrlPanel` | 保存设计、校验槽位（距离 + 是否可控）、驱动轮次、同步给附近客户端 |
| `client.screen.CtrlPainter` | 单个控件的工业风绘制（灯罩、旋钮滚花、七段数字） |
| `client.screen.CtrlCanvas` | 面板窗口的 AWT 画布、点击热区、纹理上传 |
| `client.GuiCtrlPanel` | 三个页签、拖拽排布、旋钮/滑杆映射、文本编辑、操作包与保存包 |

要点：

- **为什么用 AWT 而不是 `FontRenderer`**：3D 里逐字绘制只有一种像素字形，做不出大号读数、圆环刻度和抗锯齿曲线；整屏画成一张纹理后，十几个屏同屏也只是一堆 quad。
- **字号必须走逻辑量纲**：`DfcScreen` 的所有坐标都在 256×192 的虚拟画布上，由变换矩阵缩放到实际方块面。字号直接用逻辑像素，AWT 会在最终光栅化时按倍率渲染，所以放大后依然锐利。
- **纹理上传自己做**：不借用 MC 的共享 `DATA_BUFFER`（会被别的 mod 弄脏），按需自建 direct buffer；每块屏一张纹理，退出世界时统一释放。上传前必须把纹理单元切回 0 并走 `GlStateManager` 绑定——直接用 `glBindTexture` 会绕过它的缓存，quad 最终采样到的可能是地形图集。
- **每块屏只画一次靠结构保证，不靠判定**：控制器之外的格子是 `BlockDFCMonitorPart`，没有方块实体，想画也画不了。早期让 12 格全是控制器、再用"邻居是否已覆盖"去重的做法，会在两块屏并排时互相吞掉。
- 每块屏的重绘节流到 5Hz（开机/故障页 20Hz），空闲时完全不上传。

`tools/regcheck/check.py` 静态核对「声明了但没有注册」这一类错误——编译器看不见、进游戏才发现：

```bash
python tools/regcheck/check.py
```

它解析 `ModContent` 与 `HBMZZ` 的源码，比对四组集合：声明的 Block、注册的 Block；声明的 Item、注册的 Item；每个可放置方块是否有对应物品；每个 `extends TileEntity` 的类是否有注册名。2.3.0 里的两个 bug 正是它现在盯的东西：

- `ITEM_BLOCK_VIDEO_BROADCASTER` 声明了却没交给物品注册表 → 方块没有物品，创造栏里看不到、也放不下来。
- `TileEntityMonitorCamera` 没注册 → 它靠 `SPacketUpdateTileEntity` 同步名称与朝向，放置时 `onBlockPlacedBy` 的第一句 `setName` 就会调 `writeToNBT`，直接抛 `... is missing a mapping!`，**放下就崩**。

不启动 JVM，几百毫秒跑完，改完 `ModContent` / 任何 TE 都该跑一遍。

## 已知限制

- 墙屏是**同一台设备的渲染跨度**，不是独立的多方块结构：其余格子仍是各自的监视器方块，只靠覆盖判定跳过重复绘制。拆掉控制器（左上角那一格）时整面屏一起消失；拆中间某一格只会留下一个缺口，不会连带拆掉邻居。
- 终端窗口尺寸是**客户端本地偏好**，不随存档同步给其他玩家。
- 稳定阶段的倒计时是**预测**：基于实测的催化剂损伤增速，DFC 在无干扰器时仍可能瞬间爆炸。
- 功率计必须手动绑定；终端不会自动搜索功率计。
- 枪械是**瞬发射线**判定，没有子弹实体、弹道下坠和穿透；伤害不区分部位。
- 右键对着可交互方块（箱子、工作台等）时，开火会和方块交互同时发生，枪械没有做「交互优先级」判定。
- 首次打开屏幕时 AWT 需要探测系统字体，极少数精简 JRE 环境可能没有中文字体，此时中文会退化成方框（`logs/latest.log` 里有一行字体探测结果）。

### 已知的外部崩溃（不是本模组引起）

在装了 NTM 诅咒版（`NTM_Cursed_Edition`）的整合包里，DFC 核心附近偶发 `ConcurrentModificationException`，栈是
`com.hbm.tileentity.machine.TileEntityCore.tickClient`，里面没有一行 `com.hbmzz`。原因是诅咒版把 `dfcShocks`
这个 List 通过 `DFCShockPacket` 在 netty 线程里 `add`，而 `tickClient` 同时在主线程 `for` 遍历它。
本模组对此无能为力，只能把自己的开销压到最低：
把 `display.liveScreen` 设成 `false` 可以完全关掉方块面渲染，用于确认崩溃是否与本模组无关。

## 枪械

模组内置三把瞬发射线枪械，全部走「服务端裁判」：客户端只上报扳机是否按住，射速、弹匣、命中判定都在服务端算，改客户端转速也打不快。

| 枪械 | 口径 | 单发伤害 | 射速 | 弹匣 | 射程 | 模式 |
| --- | --- | --- | --- | --- | --- | --- |
| Mk.1 制式手枪 | 9mm | 7.0 | 0.3 秒 | 12 | 40 格 | 半自动，精度高 |
| Mk.2 卡宾枪 | 5.56mm | 5.5 | 0.15 秒 | 30 | 60 格 | 全自动 |
| Mk.3 破门霰弹枪 | 12 号 | 4.0 × 8 弹丸 | 1 秒 | 6 | 20 格 | 半自动，强散布 |

弹药统一是「弹药」物品，靠 metadata 分三种口径：9mm（每份 16 发）、5.56mm（12 发）、12 号霰弹（8 发）。

- **开火**：手持枪械按住右键；半自动枪每次按下只打一发。
- **换弹**：**潜行 + 右键**手动换弹，弹匣打空时开火也会自动换弹；换弹过程中不能开火，换弹时长写在 `ItemGun.GunType` 里（20 / 30 / 40 tick）。
- **弹药消耗**：从背包（含副手）里按口径扣除，创造模式无限。
- **视觉效果**：枪口烟焰 + 命中点粒子，声音复用原版烟花爆炸音效并随机移调；死亡消息 `death.attack.hbmzz.gun`。
- **命中判定**：`GunHandler.trace` 先做方块射线，再用 AABB `calculateIntercept` 找最近的实体，取两者更近的一个；连续射击会清零 `hurtResistantTime`，否则原版 10 tick 无敌帧会把全自动的伤害吃掉。
- 配方：手枪 `"I I"/"III"/" RG"`，卡宾枪 `"III"/"IGI"/"IR "`，霰弹枪 `"III"/"GG "/"RR "`（I 铁锭、G 火药、R 红石）；弹药为无序合成，见 `ModContent.registerRecipes`。

### NTM: 诅咒版（机器控制面板 / 机器控制台）

**本模组有两块面板，来源不同，必须分开说。**

#### 一、机器控制面板 —— 只借了机制

机制不是本项目发明的，它抄的是 NTM: 诅咒版的 `com.hbm.inventory.control_panel`：

| 取自 NTM: Cursed Edition 的部分 | 说明 |
| --- | --- |
| `IControllable` 契约 | `getQueryData()` / `receiveEvent(pos, event)` / `getInEvents()` 三个方法，以及「机器上报数据、面板下发事件」这个方向约定 |
| `ControlEvent` / `DataValue` | 事件对象（`newEvent(name)` + `setVar(name, 值)`）与「数值 / 字符串 / 枚举 / 复合」的类型体系 |
| 事件词表 | `rbmk_ctrl_set_level`、`rbmk_crane_move`、`tank_set_mode`、`turret_switch`、`turret_set_target`、`siren_set_state`、`door_toggle`、`lever_toggle`、`spinny_light_power` 等，见 `MachineBridge.KNOWN_EVENTS` 的逐条注释 |
| 控件集合 | 按钮 / 急停 / 拨杆 / 旋钮 / 滑杆 / 指针表 / 七段管 / 灯 / 文本屏的分类与语义 |

**这一块的实现是独立的**：反射桥（`MachineBridge`）、服务端的轮次引擎（`CtrlEngine`）、6 槽位 + 一句话规则的扁平模型、以及全部 AWT 绘制与窗口，都是本项目自己写的；节点图编辑器在这里**没有**被使用。`CtrlType`、`MachineBridge`、`CtrlRule` 的类注释里也标了这一处来源。

#### 二、机器控制台 —— 代码整套移植

`com.hbmzz.cecp` **逐文件移植自 NTM: 诅咒版的 `com.hbm.inventory.control_panel`**（`master` 分支），不是「参考」「借鉴」，是搬：

| 原样搬过来的部分 | 文件 |
| --- | --- |
| 控件基类与控件集合 | `Control`、`ControlType`、`controls/*`（14 个控件）、`controls/configs/*` |
| 节点系统 | `NodeSystem`、`Node`、`NodeConnection`、`NodeElement`、`NodeDropdown`、`NodeTextBox`、`NodeButton`、`nodes/*`（17 个节点类） |
| 分类注册 | `ControlRegistry`、`modular/*`（`StockNodesRegister`、`NCStock*`） |
| 值类型 | `types/*`（`DataValue`、`DataValueFloat`、`DataValueString`、`DataValueEnum`、`DataValueComposite`） |
| 编辑器界面 | `GuiControlEdit`、`SubElement*`（摆放 / 节点 / 连线 / 事件 / 变量 / 尺寸 / 控件配置）、`ItemList`、`GuiLinkerButton`、`ControlPanelViewModelPositonDebugger` 之外的全部子界面 |
| 面板模型与事件总线 | `ControlPanel`、`ControlEvent`、`ControlEventSystem`、`IControllable`、`ITypableNode` |

**改动的只有四类**，其余一行没动：

| 改动 | 原因 |
| --- | --- |
| 包名 `com.hbm.inventory.control_panel` → `com.hbmzz.cecp` | 换个门牌 |
| Java 9+ 语法降级（`instanceof` 模式匹配、`switch` 表达式、`var`、`Optional.isEmpty()`、`String.isBlank()`） | 目标是 1.12.2 / Java 8 |
| NTM 内部工具类 → `com.hbmzz.cecp.compat`（`CtrlBuf`、`CtrlImm`、`ObjModel`、`GuiFx`、`RenderUtil`、`CtrlRes`、`CPEnv`、`CPPackets`） | 诅咒版依赖 `NTMBufferBuilder` / `NTMImmediate` / `WaveFrontObjectVAO` / `MainRegistry` 等 NTM 私有类，本模组没有它们 |
| 界面显示文本英 → 中 | 用户要求；翻译边界见[汉化边界](#6-汉化边界) |

方块外壳（`BlockCtrlConsole`）、方块实体（`TileEntityCtrlConsole`）、TESR（`RenderCtrlConsole`）同样移植自诅咒版的 `BlockControlPanel` / `TileEntityControlPanel` / `RenderControlPanel`，只去掉了 OpenComputers 那一支。

控件与面板的 **OBJ 模型、贴图**也来自诅咒版，放在 `assets/hbmzz/models/control_panel/` 与 `assets/hbmzz/textures/models/control_panel/`。版权归 NTM: Cursed Edition 作者所有。
