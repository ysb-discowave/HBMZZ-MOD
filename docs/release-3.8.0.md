# HBMZZ 3.8.0 — 视频上墙：一面 32×32 的大屏，和屏正中的一台电视

> HBMZZ 3.8.0 正式发布，面向 Minecraft 1.12.2 / Forge 14.23.5.2847。
> 视频第一次能挂到墙上：**1~32 格见方的大屏、一支遥控器、一台摆在屏幕正中的电视**，F 铺满、再按 F 回到电视。
> **mp4 丢进文件夹就能在游戏里导入播放**，不用再敲命令行。
> 顺手把「4 分钟的片子只剩 2 分 46 秒」「墙上画面发灰」这些老毛病一并修了。

| 内容 | 说明 |
|---|---|
| 视频大屏 | 1~32 格见方，四个朝向一致，拆一格整面消失；右键开电视窗，F 铺满 |
| 大屏遥控器 | 两步连接：右键播放器、右键大屏，就接上了；上限 64 格 |

## 一、视频大屏

一块屏是一面墙，不是一个方块。

- **控制器 + 填充格**：只有控制器那格带方块实体，其余是同方块的填充格。画面只可能被画一次，
  不会出现「十二个控制器各画一遍」，也不会出现「谁都以为别人画了」。
- **四个朝向一致**：朝向、镜像、UV 一次算清，画面走向与玩家站在正面时的左右手一致，
  不会出现「北面正常、东西镜像、上下颠倒」。
- **尺寸 1 ~ 32 格**，从配置窗口调（蹲下右键控制器 / Shift + 右键大屏）。变大补格，
  变小只手收掉这面墙自己的格，不碰你另外放的东西。
- **拆一格，整面消失，只掉一件**，掉在被拆的那一格，不会留一地孤儿格。
- 画面贴在方块表面外 0.002 格，不与方块模型 z-fighting；几块大屏并排时互不干扰。
- 同一客户端最多同时解码 4 路大屏，超出的屏保持黑屏 —— 不让一屋子屏幕各开一条解码线程。

## 二、屏正中的一台电视

对着大屏按右键，屏幕正中会出现一台电视 —— 不是弹出一个游戏窗口，是游戏里真摆着一台电视。

- **长什么样**：外壳、边框、屏幕内圈、底座、电源灯都画出来。周围的世界压暗但不盖掉，
  所以你还看得见自己站在哪儿，也一眼知道片子挂在哪面墙上。
- **屏幕比例跟着片子走**：4:3 的片子里那块屏就是 4:3，宽银幕就是宽银幕。外壳是照着画面做的，
  不是照着画布做的；窗口再小，也会留出一个能看清的最小尺寸。
- **F 是开关，不是跳转**：按 F 收掉外壳、画面铺满，再按 F 回到这台电视，窗内右键同效。
  全屏与否由这台电视自己记账，不看桌面 —— 本来就全屏玩游戏时，按 F 只是把外壳收掉，
  游戏窗口一点不动；退出时也不会把全屏的游戏踢成 854×480。
- **ESC 原样退出**：回到看片之前的桌面状态，不留下一个被改过的显示模式。

| 手势 | 结果 |
|---|---|
| 大屏 · 普通右键 | 开电视窗（屏正中，外壳 + 底座 + 电源灯） |
| 大屏 · **F** | 收掉外壳，画面铺满；再按 F 回到这台电视（窗内右键同效） |
| 大屏 · **Shift + 右键** | 菜单：进度条 / ±5s / ±30s / 暂停 / 回开头 / 尺寸 / 全屏观看 / 关闭 |
| 大屏 · ESC | 退出，回到看片之前的桌面状态 |

菜单里的「全屏观看」等于「开电视 + 已经按过一次 F」，给习惯一步到位的人；
进度条、±秒与暂停都在这张菜单里，看片时不会误触到别的地方。
方块介绍里也写清了这套手势：右键是「屏正中开一台电视」，Shift + 右键才是菜单。

## 三、遥控器

- 物品 `hbmzz:video_remote`，16×16 手持机贴图。**普通物品，不能放置**，右键别的方块什么也不耽误。
- 两步接上：右键播放器对准 → 右键大屏（点任一格）。两者相距上限 64 格，人要够得着大屏（12 格内）。
- 绑定落在服务端：大屏记住播放器、片名、音量，播放器记住大屏。拆大屏自动解绑，不留下指空的连接。
- 接大屏只靠这一支遥控器，不用在墙上拉线。

## 四、导入：mp4 丢进去，剩下的交给它

- 蹲下右键播放器 →「导入视频…」→ 选文件 → 后台拆帧 + 音轨 + 打包，带进度、可取消；转完直接进列表。
- 容器白名单：`mp4 / mkv / mov / avi / webm / flv / wmv / ts / m4v / mpg / mpeg / 3gp`。
- 帧率档位 6 / 8 / 10 / 12 / 15 / 24 / 30 / 48 / 60 / 90 / 120，导入与读取两端都以 120 为上限。
  代价写在界面上：帧数 = 时长 × 帧率，120fps 是 30fps 的四倍帧数与体积，默认仍是 12fps。
- 包名支持中文；分隔符、空格、控制字符、结尾点号一律拒绝 —— 没有斜杠就没有目录穿越。
- FFmpeg 在线下载：64 段并行 + 断点续传，缓存在 `config/rsaudiofm/bin/`，断线不重头下；
  没有网络时 `mp3 / ogg / flac / wav / aiff` 照常可用。

## 五、播放与拉杆

- **站立右键 = 大屏展示**：接了大屏且屏在本机已加载区，片子直接放到那块屏上，客户端进电视窗 ——
  画面是屏自己的解码器给的，窗口里没有第二份播放实例。
- **蹲下右键 = 菜单**：片源、导入、打开文件夹、刷新列表、播放器设置（音量 / 强制限制返回）。
- **红石只做开停**：上升沿播、下降沿停，误触拉杆不会把谁切进全屏；首次 tick 只采纳当前信号、不动作。
- 接了屏之后播放器的普通右键什么都不开：不抢全屏、不开菜单、不动进度；没接屏时才是本机播放。
- 大屏被拆则自动解绑，拉杆回到本机播放的老逻辑。
- 片尾停在最后一帧，不自动循环；要重放按「回开头」或扳一次拉杆。

## 六、顺手修掉的几处老毛病

| 现象 | 真因 | 现在 |
|---|---|---|
| 4 分钟的片子只剩 2:46，还有声音没画面 | 播放端帧数上限写死 20000，4:23 按 120fps 是 31618 帧，读包时被切掉 | 上限提到 500000（120fps 也有 69 分钟余量）。截断在读包一侧，**旧包不用重转** |
| 音轨比画面长，或者干脆没有音轨 | 音轨取整段源视频；提取超时写死 120 秒 | 按 `frames / fps` 用 `-t` 截断，超时随时长放大 |
| 慢机 / 高分屏 / 一屋子屏：画面一帧都没有 | 播放头跑出 6 帧缓存，解码线程仍匀速往前挪，落后就再也追不回来 | 缺帧时解码线程按播放头丢帧追上去，只清过期帧 |
| 目录里的 mp4 被当成坏文件，静默忽略 | 库只认自己的包格式，别的文件连名字都不报 | 刷新时点名「待导入 N 个」，并给出「导入视频…」入口 |
| 墙上的监视器画面发灰，窗口里正常 | TESR 跑在世界渲染阶段，unit 1 还挂着光照贴图，没有自带光照坐标的四边形乘上了「上一个画过的东西的亮度」 | 画面前把光照钉到 240（满亮），画完还原。同一部片两个地方一样亮 |
| 长片转换卡在半路 | ffmpeg 输出没人读，64 KB 管道一满就卡在 write 上 | 守护线程一路读走，失败提示带上 ffmpeg 自己的最后一句话 |

> 发灰那条量化排除过：包内第 7201 帧与源 MP4 同一时刻的 PNG 参考帧比，luma 30.96 vs 30.87、
> meanRGB 差 < 1。不是转码、不是色彩范围、不是纹理格式，就是光照贴图乘了一次。

## 九、已知问题

| 问题 | 说明 |
|---|---|
| 监视器画面恒定满亮 | 这是「屏是屏」的选择：暗处也不再发灰。要氛围感得另做一条按环境光调制的通道 |
| 播放头按世界 tick 推算 | 20 tick/s，跨客户端最多差一两个 tick 的取整，肉眼不可见，但不是帧级严格 |
| 同客户端最多同时解码 4 路大屏 | 超出的屏保持黑屏，重新扳一次拉杆可再试 |
| 站立右键会让大屏真的开始播 | 那是世界状态，多人服务器上等于替所有人按下播放；停止仍归拉杆或电视窗里的暂停 |
| 播放速率固定 1x | 片子按自己的帧率放，没有变速播放 |
| 音量 200% 受系统混音器约束 | 响度到顶即止，不会破音 |
| 播放端只解图片帧 | mp4 / mkv 要先走一次导入（底层仍是 ffmpeg），不能直接拖进 `videos/` 播放 |
