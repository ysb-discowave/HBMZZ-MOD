// 逐版变更

从 2.1.5 到 2.3.1

机器控制面板、节点图控制台与视频广播器的逐版改动。每条尽量讲清「原来怎样 / 现在怎样」，而不是一句「优化了体验」。

v2.7.1 最新

掀盖那一刻崩掉的那一类原因

  • 原来怎样：2.7.0 在爆炸时会把附近的方块做成 EntityFallingBlock 抛出去。落块落地会把自己放回世界——这对石头没问题，对机器就是灾难：一根 RBMK 柱子被扔到地上，就地长出一根带方块实体、能继续运行的反应堆柱。我们自己写过「顶盖绝不能落地变方块」这条规矩，却在碎块上违反了它。
  • 现在怎样：带方块实体的方块一律不当碎块抛（hasTileEntity + getTileEntity 两道判断），石头、泥土、混凝土照旧飞。
  • 顶盖、渲染、事故推进各自学会失败。顶盖自身的 tick、客户端绘制、「哪台堆要炸」的推进循环，现在任何一处抛异常都只写一条带完整堆栈的日志，然后让位：坏掉的顶盖消失、坏掉的堆不再被盯着、画不出来的板子不画。理由很实际——熔毁本来就会把存档点着，一个因为渲染失败而关掉客户端的模组只会让玩家连崩溃报告都读不到。
  • 会点出 ntm-it。如果你的整合包里装着 ntm-it，它也在做同一套事故（自己的跳棒、自己的顶盖实体、自己的足迹爆炸，落定时还会来一发强度 50 的核爆）。两个模组同时反应在一台堆上，就是两块顶盖、两次熔毁、两种爆炸数量叠在一起。进存档后的第一次世界 tick 就会在日志里明确写出这一行——出问题时第一个该看的就是它。
  • 没有改的东西：触发条件、一分钟倒数、240→1150 的跳动曲线、两次掀盖的初速、tools/rbmkcheck 的 50 条用例全部照旧。
v2.7.0

RBMK 不再是一个 tick 就没了

  • 原来怎样：过热到 maxHeat()，基座模组在一个 tick 内把整台堆变成废墟。行为正确，但它是发生在你身上，不是发生给你看 —— 上一秒还是一台在跑的机器，下一秒就是废墟，唯一的证据是你没来得及截的那张图。
  • 现在怎样：温度超过 1000° 且 ReaSim 蒸汽爆满时，控制棒开始上下跳动；跳满一分钟后整个顶盖被炸飞，翻着跟头升空约 25 格，落回堆芯时引发二次爆炸，再被掀飞一次（这次约 113 格），最后落地、冒烟，堆芯按基座模组自己的方式熔毁。
  • 跳动直接用诅咒版的。不是新画一套动画：诅咒版附属在 TileEntityRBMKBase 上加了 leafia$damage 字段，它的跳动、棒底喷流、落回时的撞击音全部由这个字段驱动。我们只负责决定要多少（一分钟内从 240 抬到 1150），把动画交给它 —— 两套动画叠在同一根棒上只会打起来。
  • 为什么停在 1150。那个字段到 1200 时附属自己会调 meltdown()。写超过去，堆会在我们的倒计时结束前被基座模组拆掉，顶盖永远不会飞 —— 一段看起来能跑、只在真堆上才失效的死代码。
  • 沸腾到爆炸之间，热量被按住了。这一个小时（一分钟）里每根柱子的 heat 被钉在 maxHeat()-50：不钉住，基座模组会在头几秒内走到自己的熔毁线，倒计时还没走完堆就没了。钉子由爆炸自己拔掉。
  • 顶盖是实体，不是方块。落地时把自己放回世界会在原地生成一根活的 RBMK 柱——一台从瓦砾里长出来、带方块实体、能继续运行的堆。所以 EntityRbmkLid 只是实体：带着原堆每根柱子的顶盖、按原样排布、按各自的 cover 贴图上色；落点不改写世界，只炸、只掉碎块。
  • 「蒸汽爆满」有两种判法，取并集。一是对着 maxSteam（16000）比；二是总量连续两次扫描不涨。后者是必须的：好几个整合包把容量改到 80000 而字段还是 16000，只看字段的话 20% 就判满，堆会在完全没到极限时炸掉。
  • 配置：rbmk.surge（总开关，关掉就是原来的一个 tick）、rbmk.heat（默认 1000）、rbmk.jumpTicks（默认 1200 = 一分钟）、rbmk.blastPower（默认 10）、rbmk.melt（顶盖落定后是否交给基座熔毁）。
  • 新增 tools/rbmkcheck（50 项）。熔毁是唯一没法「跑一遍看看」的功能——跑完存档就烧了。所以判断「什么时候开始、警告多久、哪些柱子是一台堆」的那一层被写成不含任何 Minecraft 类型的纯函数，50 项离线用例逐条验：一分钟倒计时不提前、跳幅单调且始终低于 1200、蒸汽只有一半满时不许触发、对角线不算相邻、相邻但不同高度不算一台、顶盖布局字符串往返不丢半格偏移。
  • tools/regcheck 加 5 条（共 33 条）：源码里不许出现 import com.hbm.*（基座模组是反射调用的，一旦变成编译依赖，这个 jar 就只能在那个确切版本上加载）；反射只许待在 RbmkParts；请求的跳动值必须低于 1200；飞行中的顶盖不许写方块（setBlockState 出现即报红——那正是顶盖变成反应堆的写法）；判断层不许 import Minecraft（否则 rbmkcheck 跑不动）。
v2.6.1

归类不再量距离：一台终端就是一台反应堆

  • 删掉了 6 格距离分簇。v2.6.0 用「同族零件相距 ≤ 6 格」判断哪些零件属于同一台反应堆。这个半径替玩家回答了一个玩家没问的问题：30 格宽的 DFC 会被判成好几台，锅炉装在隔壁房间的反应堆会被拆开，而两台碰巧贴着盖的堆又会被并成一台——三种情况都没法反驳。
  • 现在槽位边界＝这块终端绑定的零件。折叠只看两样：方块实体类名（同族）和绑定关系（哪块面板／控制台接了它）。坐标完全不参与，所以多大的 DFC、隔几堵墙的反应堆，都还是同一个槽位。
  • 顺带补上 DFC 的族表。NTM 的 DFC 零件不是按反应堆命名，而是按它干什么命名：TileEntityCoreEmitter、CoreInjector、CoreReceiver、CoreStabilizer、CoreDetonator、CoreExchanger，加上核心本身 TileEntityCore —— 没有一个含「DFC」三个字。所以只写一条「含 DFC」的规则，大 DFC 会散成「发射器一个槽、注入器一个槽」。现在七个组件类都归 DFC，核心那一条是精确匹配（=TileEntityCore），否则它会把这个命名空间下的所有类一起吞掉。
  • 两台反应堆怎么分开：再放一块终端。这也正是玩家描述「我有两台堆」的方式——按一次绑定，而不是量一段距离。代价写在明处：两台堆接到同一块面板上会并成一个槽位、一条 set 两台一起动。
  • 同名广播的范围跟着改。命中条件是被同一块终端绑在一起 + 同部件类型 + 同部件名称，不再要求几何相邻。仍然不跨终端、不跨族，单次上限 32 台；整组写入与多目标节点广播仍然不二次扩散。
  • 自检加 2 条（tools/regcheck，共 28 条）：归类不许再出现量坐标的代码（PartTypes 里出现 Math.abs 即报红，因为任何距离判定都得用它），GroupedHost 必须走 byFamily；PartBroadcast.peersOf 的对端必须来自面板绑定表，不许再自己做分组。tools/termcheck 加 7 条纯分类用例（相距 120 格仍折叠、折叠保持面板顺序、认不出族的零件各自成槽、同一位置绑两次只算一台，以及 3 条类名归属），共 67 条。
  • 不再有的行为：槽位标签不会因为两台堆贴在一起而变成 RBMK#2——按绑定分槽之后，同一块面板上的同族零件永远只有一个槽。
v2.6.0

一台反应堆就是一个部件类型

  • 新增：同一类别的机器折进同一个槽位。一台 RBMK 是十几个方块实体——燃料通道、控制棒、蒸汽发生器、吊车台。以前它们各占一个联动器标签，窗口里就是十几个标签、十几次 use；现在同族、同一台反应堆的零件只占一个槽位（RBMK），一个窗口调整台堆。
  • 归类是三级，全部自动：①部件类型看方块实体类名（含 RBMK → RBMK 反应堆，含 DFC → DFC 反应堆，储罐／炮塔／警报／门／电源盒／警示灯／控制台各自一族，表里没有的类各自成族，不合并）；②同一台反应堆按同族零件的切比雪夫距离 ≤ 6 格链式分簇，所以大堆仍是一簇、隔开的两台堆是两个槽（RBMK#2）；③部件名称是机器类型名（「RBMK 控制棒（手动）」），广播就认它。
  • 只在同族 ≥ 2 台时折叠。单独一台仍用它原来的标签（A、你起的名字），六台互不相干的机器那块面板和以前完全一样；没接机器的空槽也留在原位，标签条不会塌成「只剩接了线的几个」。
  • 读是整组，写是分流。read 的数值键给最小–最大（40/40/40/80 显示 40–80），文本键给不同取值；keys／events／变量名取并集；新增 parts 列点名册（有哪些名字、各几台）；set／ev 成功后回一行实际台数 ×4。
  • 新增：同名零件自动广播。任何一条写入——旋钮、面板规则、CE 节点图、终端——落到一台已绑定机器之后，会复制给同面板 + 同部件类型 + 同部件名称 + 同一台反应堆的伙伴，不跨机组、不跨族、不跨面板，单次上限 32 台。两个例外不扩散：部件类型槽位上发起的整组写入，以及节点图一次发往多个位置的广播——它们本来就是发给整组，再扩散会变成 N×N 次投递（瞬时按钮会被按两次）。
  • 钩子只有一个。MachineBridge.fire 改成转调 fireAll，广播挂在 fireAll 上：以后新增任何写入路径都不可能「忘记广播」，就像它不可能忘记发送事件本身。
  • 自检加 5 条（tools/regcheck，共 26 条）：fireAll 必须还挂着 PartBroadcast.fanOut；PartGroup.fire 与 ControlEventSystem.broadcastEvent 必须自己打开范围闸（否则 N×N 投递）；TerminalShell.execute 不许直接收裸 host（否则静默退回一标签一槽）；部件类型表必须还认得 RBMK 与 DFC。tools/termcheck 同时加了 14 条组用例（按名字计数、事件分流、只投递一次、parts、×N、聚合读数、无世界时不折叠），共 60 条。
  • 已知边界：两台贴着盖的反应堆会被认成一簇——它们之间没有超过 6 格的空地，几何上没有别的办法区分。真要分开，中间留 6 格以上的间隔。
v2.5.1

中文槽位名不再印成豆腐块

  • 修：终端输入行左边的提示符，槽位名是中文时变成一排空方框。自研面板的槽位是 A–F，提示符永远只有三个字母，所以这个位置一直用等宽字体画也没人发现；CE 控制台的槽位是你自己起的中文标签（反应堆），等宽字体没有汉字，AWT 就画它自己的「缺字」方框——不报错、不崩溃，只是看起来像坏了一样。
  • 根因不是漏了一个字体调用，而是「量宽度和画字各挑各的字体」。现在窗口里所有文字都走同一个入口：字体由要画的那个字符串决定（有汉字就用中文字体，纯 ASCII 才用等宽），量宽度、算光标位置、按像素裁剪用的是同一个函数。两边不可能再算出不同的宽度。
  • 顺带修掉同类的两处：DFC 监视器终端标题右侧的「· 核心名」，以及底部状态条变成「数据中断」时（那一条平时是纯 ASCII，只有断开时才带上汉字）。
  • 自检加 2 条（tools/regcheck，共 21 条）：终端窗口里不许再手工取等宽字体（字体必须由字符串决定）；build.gradle / mcmod.info / HBMZZ.VERSION 三处版本号必须一致。都做过回退验证。
  • 附带：日志里那句 Client attempting to join with ... hbmzz@2.0.0 终于是对的版本号了——HBMZZ.VERSION 是编译期常量，从 2.0.0 起就没跟着升过，五个版本的日志都在报旧号。现在由上面那条自检盯着。
v2.5.0

终端搬进 CE 控制台

  • 新增：CE 控制台的自定义控件列表里多了「终端」。就是那个从诅咒版移植过来的控制台：放一个终端控件，用联动器给它起名字绑上机器（名字就是槽位名），右键它打开命令窗口。原来终端只长在模组自己的控制面板上，这次按同一个用法搬到了移植面板里，而不是反过来给模组面板加功能。
  • 槽位不再只有 A–F。CE 控制台每个控件各有一套 taggedLinks，槽位就是你在联动器页签里起的那个名字。于是 use 后面可以写名字（带空格也行，例如 use RBMK 控制棒组），也可以写序号；ls 仍用 * 标当前目标。
  • 命令语言抽成与面板无关的一层。两块板子不共享任何一个类，所以补全与执行都写在一个 TerminalHost 接口上：动词、提示、错误文字只有一份。终端装在哪种面板上，语法都一样。
  • 目标选择跟着存档走。选中的槽位存进控件自己的 vars，随面板 NBT 一起保存；槽位顺序按标签名排序而不是联动器的插入顺序——那块 map 是从 HashMap 重建的，两次读档可能给出不同顺序，第 2 个槽位换台机器比没有槽位更糟。序号越界时退回第一个，而不是让四个槽位列着却一个都读不了。
  • Tab 补全不发包。服务端每次回包都带上槽位表，以及当前目标的可读键名、事件和变量名；客户端对着本地这份副本补全，一次按键零往返。执行仍然只在服务端——客户端只发一行文本和一个控件序号，服务器用自己的面板解析。
  • 限流：一个终端每秒最多 10 行，超了直接回「命令太频繁了」，免得一条命令刷爆机器的事件总线。
  • 自检加 3 条（tools/regcheck，共 19 条）：addon 控件类型必须有中文名（漏了就把英文键塞进中文菜单）；写出来的控件类必须真的进注册表（2.3.0 就是这么丢的物品和 TE）；注册名不得重复——重复在 put 时静默覆盖，面板照常加载，只是少了一个控件。三条都做过回退验证，确认会红。
  • tools/termcheck 换成新接口，并加一组 host 用例：按名字 / 前缀 / 字母解析槽位、带空格的 use、以及快照补全与 ls 的标记。
v2.4.2

控制台编辑器一开就崩

  • 修：控制台编辑器（CE 控制台）打开即崩。崩溃报告只显示 updateScreen 里的 ArrayDeque.getFirst()，真凶在两帧之前：ControlType 的类型表是静态初始化时一条条填的，而 addon 的 3 个类型要等某个类第一次碰到它们才登记；编辑器的类型菜单正好一边遍历这张表、一边通过注册表解析每个类型——解析就触发了那 3 条登记，等于往自己正在遍历的列表里追加，于是 ConcurrentModificationException 打断 initGui，元素栈没被填上，下一 tick 才崩在空栈上。
  • 类型表在启动时就补齐。注册表初始化时先强制登记 addon 的三个类型，之后再没有任何代码能改这张表。
  • 菜单遍历快照。类型列表改成 ControlType.all() 的副本，按钮 id 与点击时解析用的也是同一份快照——表后来变长也不会让按钮错位。
  • 编辑器不再被一个子菜单带走。元素栈先入栈再初始化子元素，所有取栈顶都改成可空；某个子元素 initGui 抛异常只记一条 ERROR，界面照常打开。一个 bug 不该以另一个更严重的面目出现。
  • 修：窗口缩放（F11 / 改 GUI 缩放）会让类型菜单里的按钮累积一份副本，越缩越多。
  • 新增自检 tools/cecpcheck（8 项）：断言「注册表 init 之后类型表就是完整的」，并在同一进程里按菜单的方式遍历一遍——修复前是 9 个类型、遍历中变 12 个。
  • regcheck 加两条：编辑器不得无保护地取空栈顶；类型表只能通过 all() 读，字段不得再变回 public。
v2.4.1

终端里的豆腐块

  • 修：ls 用来标当前目标的 ▸ 在终端窗口里显示成方框。窗口是逐行选字体的：带中文的行走中文字体，而 Microsoft YaHei / SimHei 都没有 U+25B8；恰好机器名都是中文，于是这个标记只在最该看清的那几行坏掉。现在换成 *，四个候选字体都有，宽度也只差 1 像素，名字列不会歪。
  • 修：补全列表角上的 +N 原来压在候选文字尾巴上，看起来像名字的一部分。给它留了单独一列。
  • 修：视频广播器里 ✔ / ⚠ 两个符号同样缺字形（原版字体也没有），改成文字加颜色区分。
  • 新增自检：tools/regcheck 第 14 条扫全部字符串字面量，凡是不在四个字体交集里的装饰符号都报红并给出文件行号——这类「编译通过、进游戏变方框」的问题不该靠眼睛发现。
v2.4.0

控制面板的终端

  • 新增控件「终端」：放在面板上，右键开一个命令行窗口，用 ls / use / read / ev / set 直接读写 A–F 上绑定的任意一台机器——不必再为了一个读数摆一排表盘。
  • 目标机器随时切换。窗口上方 A–F 六个标签点一下就换，也可以打 use B；当前目标写在提示符里（B>），并随面板存档同步，多人看到的是同一个目标。
  • Tab 补全按上下文给选项：命令名、已绑定槽位、当前机器的数据键、该事件携带的变量（ev rbmk_ctrl_set_level 之后补出 level=）。Shift+Tab 反向，↑↓ 取回历史，PgUp/PgDn 翻屏。
  • 命令在服务端解析。客户端只送一行文本，不送机器坐标、不送事件名——终端的安全边界因此与旋钮完全一致：能做的手动也能做，做不到的照样做不到。
  • 终端命令限速每秒 10 条；失败会说明原因（没选目标 / 槽位是空的 / 机器已不在 / 事件被拒），不给沉默。
  • 刚放下的终端会自己指向第一个已绑定槽位；目标槽位被解绑时自动回落到下一台，不会挂在一格空气上。
  • 离线自检 tools/termcheck（38 项）跑的是真 TerminalShell，覆盖补全的起始位置、前缀过滤、变量补全与命令分发；tools/regcheck 加三条：每种控件是否都有绘制分支、是否都有面板说明、终端的命令表与 help 文本是否一致。
v2.3.2

连不上的线，点不开的窗

  • 修：视频广播器右键没有反应。方块在客户端调 openVideoBroadcaster 开窗，而 ClientProxy 没覆盖这个方法，落回 CommonProxy 的空实现——于是手挥了，什么都没有发生。
  • 修：监控屏连不上任何东西。1.12.2 只在方块拒绝这次右键之后才调用 Item.onItemUse，而监控屏的 onBlockActivated 永远返回 true：拿数据线点屏，屏幕只是打开终端，绑定代码一次都没被执行过。现在拿着数据线时方块让位，点屏即绑定；数据线里没有记录时仍然打开终端。
  • 修：摄像头没接进绑定流程。数据线点摄像头只会落到「已记录坐标」，监控屏也没有任何地方调用 setCameraPos。现在点摄像头记录、点屏绑定并自动翻到第 4 页；潜行点屏断开。
  • 修：摄像头绑定不存档。屏幕只存「看哪」，这两个字段没写进 NBT，退出重进就断线。
  • 摄像头画面改 100 ms 缓存：墙面渲染器与窗口本来就每帧取一次，一帧 160 条射线、每条约 72 次方块查询，等于在渲染线程上按 60 Hz 空转。
  • 服务端不再为读一个名字去跑整幅画面：snapshot() 每轮询一次就射线追踪一遍再把像素扔掉。
  • tools/regcheck 加三条：proxy.openX 是否在 ClientProxy 有实现、代码里用到的翻译 key 是否两种语言都有、绑定目标方块是否把右键让给了数据线。

v2.3.0

视频广播器

  • 新增方块「视频广播器」：红石上升沿一到，把选中的玩家屏幕整个换成一段视频，播完自动恢复。
  • 红石按 tick 轮询判定（不会漏边沿），只认上升沿；进存档 / 区块重载后的第一个 tick 不触发，高频时钟走冷却。

  • 解码在后台线程，只保留固定帧数的窗口；播放按时钟走，跟不上就丢帧而不是把声音拖慢。

  • 新增 tools/video/pack.py（mp4 或现成图片 → 包）与 tools/videocheck（离线验证包能被读出来）。
