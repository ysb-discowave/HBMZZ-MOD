# HBMZZ 品牌资产

这个目录里的每个位图都是 `logo-mark*.svg` 或一次封面拼版的**导出结果**，不是手绘的。
改样式只改 SVG，然后跑：

```bash
python tools/brand/render.py
```

`render.py` 会覆盖本目录下所有 `.png` 与三张封面 `.svg`。**不要直接改 PNG**——下次
跑脚本就没了，而且文件里写不进任何可追溯的信息。

## 一、文件与用途

| 文件 | 尺寸 | 底色 | 用在哪 |
|---|---|---|---|
| `logo-mark.svg` | 矢量（64 网格） | 透明 | 站点导航、深色背景、README 里内联引用 |
| `logo-mark-compact.svg` | 矢量（64 网格，无螺钉、加粗） | 透明 | ≤48px 的任何位图都从它出 |
| `logo-mark-light.svg` | 矢量 | 透明 | 浅色背景（白纸、浅灰页、文档导出） |
| `logo-mark-mono.svg` | 矢量 | 透明 | 单色印刷、水印、只能上一色的场合 |
| `logo-ost.svg` | 矢量（64 网格） | 透明 | 原声（OST）的标，深色背景用 |
| `logo-ost-compact.svg` | 矢量（64 网格，无螺钉、加粗） | 透明 | ≤48px 的 OST 位图都从它出 |
| `logo-ost-light.svg` | 矢量 | 透明 | OST 标压在浅色背景上时用 |
| `logo-favicon.svg` | 矢量 64 网格，**自带底板** | 深底 | 16/32/48 的源文件 |
| `logo-appicon.svg` | 矢量 64 网格，**满幅底板** | 深底 | 180/192/512 的源文件 |
| `logo-lockup.svg` | 矢量 560×128 | 透明 | 横排版（标 + 字 + 副标），浏览器里用 |
| `logo-mark-512.png` / `-1024.png` | 512² / 1024² | 透明 | 通用大图、PPT、宣传物料 |
| `logo-mark-light-512.png` | 512² | 透明 | 浅底场景的位图版 |
| `logo-ost-512.png` / `-1024.png` | 512² / 1024² | 透明 | OST 标的大图版（片尾卡、封面外的物料） |
| `logo-ost-light-512.png` | 512² | 透明 | OST 标的浅底位图版 |
| `favicon-16/32/48.png` | 16² / 32² / 48² | 带底板 | 浏览器标签页 |
| `apple-touch-180.png` | 180² | **满幅深底** | iOS 主屏图标 |
| `icon-192.png` / `icon-512.png` | 192² / 512² | **满幅深底** | Android / PWA / 通用应用图标 |
| `ost-cover-thumb-256.png` + `.svg` | 256² | 深底 | 原声页专辑头的 68px 缩略图 |
| `repo-cover-1280x640.png` + `.svg` | 1280×640 | 深底 | GitHub 仓库社交预览 |
| `og-1200x630.png` + `.svg` | 1200×630 | 深底 | 页面分享卡（`og:image`） |
| `ost-cover-1024.png` + `.svg` | 1024² | 深底 | 原声页的专辑封面、系统媒体面板 |

为什么小图标要**自带底板**：`logo-mark` 的边框是钢色 `#e6ecf3`，压在浅色标签栏上等于
看不见——浏览器标签页多半是浅色的。所以 favicon 用的是另一份源文件：深色圆角砖 + 白 H +
琥珀横杠，浅色与深色标签栏上都立得住。**不要**把透明版直接缩成 16px 当 favicon。

为什么应用图标要**满幅**：iOS / Android 会自己裁圆角，留白与描边只会变成一圈多余的边。
`logo-appicon.svg` 的底板铺到画布四边，圆角交给系统。

为什么小尺寸要单独一套：`logo-mark.svg` 的四角螺钉在 16px 下只有 0.75 像素，实际效果
是四团噪点。`logo-mark-compact.svg` 去掉了螺钉、把边框从 3.5 加粗到 5、立柱从 7 加粗到 8，
这是 16px 还能认出"H + 琥珀横杠"的唯一办法。

## 二、三个应用位置的规格

### 1. 站点导航（六个页面）

```html
<img class="brand-mark" src="assets/brand/logo-mark-compact.svg" alt="" width="22" height="22" decoding="async">
```

- 显示尺寸 **22×22**，与 16px 的字号配合（`.brand` 的 `gap: 9px`）
- 用**紧凑版**而不是 `logo-mark.svg`：后者边框 3.5 单位，22px 下只有 1.2 像素，会发虚；
  紧凑版 5 单位（1.7px）配粗体字才站得住
- CSS 只加了 `drop-shadow(0 0 6px rgba(245,165,36,.22))`，让钢色边框在 `#0a0c0f` 上
  不至于糊掉；**不是发光特效**，别加大
- 页脚里那处品牌用的是同一份文件、同一个类，不另存一份图
- 换了文件不用改 HTML：路径是固定的

### 2. OST 标（`logo-ost*.svg`，原声专属）

主标屏框里是 `H`，OST 标的屏框里是**三根琥珀色电平柱**（底边统一压在 y=47，
高度 14 / 30 / 21）。除了屏里的东西，两者同一块屏、同一组数值：边框 `3.5`、
圆角 `3`、四角螺钉 `9.5`——所以并排放着像同一台机器的两个通道，而不是两个模组。

为什么是电平表，不是音符 / 波形 / 耳机：

1. 三根柱子底边对齐，缩到 22px 还是三根数得清的柱；音符的符头和耳机的耳罩
   在那个尺寸会糊成一团（实测 22px 下仍可辨，见 `logo-ost-compact.svg`）
2. 模组自己的 `AlertScreen` 屏上就有电平条，这属于同一套工业语言，不是借来的音乐符号
3. 全标只有琥珀一处彩色，和主标一致，两个标贴在一起不抢

用在哪：

- **原声页的专辑头**（`ost.html` 的 `.ost-cover`，68px）——渲染源是
  `ost-cover-thumb-256.png`，那张缩略封面拼的就是这个标
- **系统媒体面板**（锁屏 / 播放器小组件）——`site.js` 的 `MediaMetadata.artwork`
  用的 1024 封面，同样拼的是这个标
- 片尾卡、物料用 `logo-ost-512.png` / `-1024.png`

**不要拿它当 favicon**：和主标一样是透明底、钢色边框，压在浅色标签栏上等于没有。
浏览器页签统一用 `logo-favicon.svg`（主标带底板版），原声页也是。

### 3. OST 封面（`ost.html`）

```html
<img class="ost-cover" src="assets/brand/ost-cover-1024.png" width="68" height="68" loading="lazy">
```

- 版面上 **68×68**（窄屏 54×54），圆角 `2px`、描边 `1px var(--line)`
- 用的是 **`ost-cover-thumb-256.png`**，不是 1024 那张：1024 的构图缩到 68px，标只剩 15px，
  看上去就是"空方块里一个小点"。缩略版把标放大到占满、去掉了小字
- 源图是 1024²，等比缩到 68 不会失真；`width/height` 写死是为了避免加载时跳动
- 两张封面的顶上都拼 **`logo-ost.svg`**（见上一节），不是主标；`render.py` 里
  靠 `cover_svg(..., mark="logo-ost.svg")` 指定，改封面别把标换回 `H` 那版
- 底部 96px 是安全边：平台把它裁成圆角或加角标时不会切到字
- **它不是曲子的封面**。三首的源文件都是黑屏导出，本来就没有美术；这张图属于站点。
  页面文案里写明了这一点，改版时不要把它说成"专辑封面"
- 系统媒体面板（锁屏 / 播放器小组件）用的也是这张，注册在 `site.js` 的
  `MediaMetadata.artwork` 里，另带一张 `icon-512.png` 兜底

### 4. 仓库封面（GitHub）

`repo-cover-1280x640.png` 是 GitHub 社交预览的规格（1280×640，宽高比 2:1）。

**这一步只能手点**：GitHub 没有提供设置社交预览的 API。仓库 → Settings → General →
Social preview → Upload an image，传这张 PNG。传完在 Issues / PR / 分享链接里看到的
就是它。

`og-1200x630.png` 是给网页用的（`og:image`），两者构图相同、比例不同，不要混用：
社交预览按 2:1 裁，1200×630 接近 1.9:1，混用会切掉边的字。

## 三、替换与改动规则

1. **改形先改 SVG**：`logo-mark*.svg` 与 `logo-ost*.svg` 是唯一真相。改完跑 `render.py`，别手改 PNG。
2. **保持基名**：`logo-mark-<尺寸>.png`、`icon-<尺寸>.png` 的命名被 `render.py` 与 HTML
   共同依赖，改名字要两边一起改。
3. **不要非等比缩放**：所有位图都是按目标像素等比导出的。在 HTML 里同时写死
   `width`/`height` 时要保证比例与原图一致，否则标会变形——这是最常见的坏用法。
4. **留白不要小于 8%**：标的边框离画布边缘至少 8%，低于这个值在圆角容器里会被切。
5. **不要在深色底上换用浅色版**：`logo-mark-light.svg` 的墨色是 `#0a0c0f`，压在深底上
   等于没有。
6. **不要给 PNG 加字**：文案走 SVG 封面或页面文字。位图里加字以后改不动，也搜不到。

## 四、颜色与字体（与 `docs/assets/site.css` 一致）

| 角色 | 色值 | 用在哪 |
|---|---|---|
| 钢板 | `#e6ecf3` | 深底版的边框与立柱 |
| 墨 | `#0a0c0f` | 浅底版的边框与立柱、封面底色 |
| 琥珀 | `#f5a524` | 横杠，全标唯一一处彩色 |
| 深琥珀 | `#d8871a` | 浅底版的横杠（`#f5a524` 压白对比不够） |
| 螺钉 | `#48525f` | 仅大尺寸版本 |

字体：封面里的字用等宽栈 `Consolas, 'Cascadia Mono', 'Courier New', monospace`，
中文副标题用 `'Microsoft YaHei', 'PingFang SC', sans-serif`。**SVG 里的文字依赖阅读端
有这些字体**，所以对外分享请用导出的 PNG；SVG 留给浏览器与本地排版。
