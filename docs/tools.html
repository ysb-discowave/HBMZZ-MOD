reasim 工作台

模组里音频播放器那台「装在铁皮箱里的破喇叭」的信号链，搬到了网页上。拖文件进来、调五个参数、试听，然后批量导出 16-bit WAV。

算法逐行移植自 com.rsaudio.audio.ReasimDsp，系数与处理顺序和游戏内一致。所有处理都在你的浏览器里完成，文件不离开本机。

    信号链（固定顺序，与游戏内一致）

    1. ①增益（0–200%）
    2. ②失真：tanh 软削 + 位深 16→6 + 去直流
    3. ③电流声：50Hz 基波 + 二、三次谐波（不随音量）
    4. ④沙沙声：带限白噪 + 稀疏爆裂
    5. ⑤回声：一阶低通反馈，延迟 90–280ms 随湿声
    6. ⑥软限幅 ±0.95

    几点说明

    这个工作台是离线批处理工具，不是游戏内播放器。能做的、做不了的，先说清楚。

    关于回声（房间自动）

    游戏里的「回声自动」是客户端实时探测房间大小。工作台没有真实世界，所以搬了一个手动版：六个方向各给一个 0–16 格距离滑条（0 = 贴墙、16 = 望不到头）+ 周围实心方块占比 + 「头顶看得到天」开关。算法与 ReasimEnvironment.java 同构——0.85 × 密闭度 + 0.35 × (实心占比 − 0.40)，露天再乘 0.35，结果钳在 0–0.95。关掉自动开关就退回纯手动回声滑条，数值含义与游戏内手动模式一致，延迟 90ms（0.00）到 280ms（1.00）。

    关于输出格式

    统一输出 16-bit PCM WAV，文件名加 _reasim 后缀。任何格式的源文件都可以进来（只要浏览器会解码），出来的永远是 WAV。

    关于隐私与速度

    文件在你本机解码、处理、导出，全程没有上传。逐采样 + 大整数噪声源，一首 10 分钟的歌大约 20–60 秒；批量时一个一个来，不抢 UI 线程。

    和游戏里的差异

    信号链逐采样一致：Padé 近似 tanh、一阶低通反馈、xorshift64* 噪声源、软限幅系数全部来自 ReasimDsp.java。房间回声公式照 ReasimEnvironment.java 移植，唯一差别是「六个方向射线」改成了六个滑条，由你自己填。
