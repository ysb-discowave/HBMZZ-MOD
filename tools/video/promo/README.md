# HBMZZ 宣传片

一支 **7 分 17.8 秒**（437.833 s / 10508 帧 @24fps）的模组宣传片。

- 片头 **0–8 s**：固定素材 `tools/video/intro/out/hbmzz-intro.mp4`
- 正文 **8–244 s**：13 段，全部程序生成（236 s / 472 拍）
- 片尾 **244–437.833 s**：固定素材，致谢名单，自带音乐 `The ending of melting`

片头片尾一字未改。正文用真实游戏贴图 + 官方主视觉，做工业信息设计风格的动态图文。

**主题句**：核电厂的每一块屏，都该说同一件事。

## 接入正式 BGM（下一步就做这个）

现在成片的音轨是**占位**：正文 8–244 s 静音，244 s 起接片尾自带音乐。流结构与最终版完全一致，换音乐不动画面。

```bash
py -3.12 tools/video/promo/make_promo.py \
    --bgm "path/to/bgm.wav" \
    --bpm 128 \
    --offset 0.0 \
    --duck-credits 0.6
```

| 参数 | 作用 |
|---|---|
| `--bgm` | 音乐文件。任意格式，ffmpeg 会转 48 kHz 立体声 AAC |
| `--bpm` | 音乐的 BPM。**关键**：段落时长都是整数拍，改 BPM 会按 `beats` 重算每段帧数，然后提示你重渲染。**不是拉伸画面**，所以卡点是真的卡点 |
| `--offset` | BGM 第一拍相对正文起点（8.000 s）的偏移，秒。用来把重音对到关键帧 |
| `--duck-credits` | 正文末尾淡出 / 片尾音乐淡入的时长 |
| `--same-track` | 若正文 BGM 与片尾曲是同一首，接成连续一条，不做交叉淡化 |

`out/CUE.md` 里有全部段边界与 16 个建议重音点的时码，对着音乐核一遍即可。

**注意**：改 `--bpm` 会让脚本退出并提示重渲染全部段。这是刻意的——我们要的是真卡点，不是把画面拉伸变形。

## 技术取舍（为什么这么做）

**全片零重叠拼接。** 不用 `xfade`，所有转场在段内实现。所以总帧数严格等于各段之和，段边界帧号任何时候都能算准，换 BPM 重排也不会漂移。

**段落时长用「拍」定义。** BPM 120 时 1 拍 = 12 帧，472 拍 = 236 秒。BGM 到位后改 BPM 是重算帧数并重渲染，不是拉伸画面。

**字幕烧进帧，不做后期叠加。** 字幕由段渲染器逐帧画，所以字幕与画面元素天然同步，不会出现"字到了元素还没到"。

**片尾 12 fps 上采样到 24 fps 用重复帧。** 画面不变，换来全片只有一个帧率。

**颜色只用品牌四色** `#0a0c0f` / `#e6ecf3` / `#f5a524` / `#48525f`，外加一个受限警示红 `#b3261e`（只准出现在 S01 数据冲突与 S10 八级代码最高级，各 ≤6 帧）。HBMZZ 讲核事故，完全没有红的危险表达会让「八级代码」失去说服力；但品牌表达仍然只用四色。

**不用绿色表达状态。** 全片没有"绿色=正常"的用法，一致性靠"六屏数值完全相同 + 钢色勾边"表达。

## 已知限制

1. **没有游戏内实录**。仓库里没有任何游戏内录像，所以画面是"贴图 + 程序绘制的 HUD"，不是真的在跑的方块。S04 的"读数一模一样"是渲染参数相同，不是真的采样两次。缓解靠文案（「这些数字不是贴图」）。
2. **片尾占 44%**。193.8 秒是固定素材，含完整署名与授权链，这一版按所有者要求保留完整。
3. **`--bpm` 未实测过真实音乐**。BGM 到位前，拍网格按 120 BPM 假设。
4. 段渲染器用 Pillow 逐帧绘制，**做不了真 3D**（没有高光/反射）。S03 的机箱是等距投影的平面拼合，靠明暗面和细线营造实体感。
