// 附加包

两个包，各管一段

从 2026-11-17 起，HBMZZ 拆成两枚 jar：本体 hbmzz 与 控制台附加包 hbmzz:addon。这不是打包习惯上的调整—— 是因为两者里的代码来源不同、许可也不同，混在一份 GPL-3.0 声明里说不清楚。

// 为什么拆

许可不一样，就不能装进同一个声明

控制台那套面板（com.hbmzz.cecp）是从 NTM: 诅咒版 移植的，GPL-3.0，没问题。 但面板里那些仪器控件来自 NTM Cursed Addon，它在 2026-10-23 改成了 PolyForm Shield 1.0.0。

PolyForm 允许修改与再分发，但它的 No Other Rights 一节写明不得 sublicense， 还带一条 noncompete。把它们塞进「整仓库 GPL-3.0-only」里，等于替对方做了一份它没给的授权， 同时也没把它的条款传给拿到 jar 的人。

所以：本体继续 GPL-3.0-only，附加包自己声明 PolyForm Shield 1.0.0， 各自随包附各自的许可文件。

// 怎么装

两个都放进 mods 就行

依赖方向只有一边：附加包依赖本体。单独装本体照常可用；单独装附加包能启动，但引用不到任何宿主接口，等于空跑。

名字说明：hbmzz:addon 是这个附加包的项目名，不是 modid——命名空间不能带冒号。它的 modid 是 hbmzzaddon；方块、方块实体与资源域仍沿用 hbmzz，因为那些名字写进了旧存档。

包里面有什么许可
hbmzz
本体		 监控屏、核事故系统、DFC 系列、红石音频、三首 OST GPL-3.0-only
hbmzz:addon
附加包		 控制台方块、节点图编辑器、面板仪器 PolyForm Shield 1.0.0
旧存档：注册名（hbmzz:ctrl_console 等）一个字都不改， 所以装回两个包之后，原来的控制台还会在原来的位置。反过来说：拆掉附加包，控制台方块连同里面存的面板内容都会一起消失——它们都在后者里。
