// 使用指南

从放下监控屏，到真的操控一台机器

HBMZZ 在方块正面画了一台工业控制台：你能用终端调它、用面板工坊给它写报警规则， 再接上节点图控制台去操控反应堆。下面按六块功能拆开讲，每块都只说仓库文档里写明的操作与行为。

// 实时屏幕

方块正面是一台真在绘制的显示器

全部内容用 Graphics2D 画到一张位图，再作为单个纹理贴到一个 quad：21px 大号读数、10px 中文标签、真圆环刻度与抗锯齿曲线能同屏出现。画布按 256×192 逻辑像素排版、实际纹理 768×576（3 倍超采样）；墙屏可跨 1–4 格宽、1–3 格高，内容始终按 4:3 等比缩放居中、不拉伸。整面墙只渲染一次——只有控制器格有方块实体，其余是占位块。

02

开机、坠落与离线

开机流程：AHBSSMFI-OS 启动画面（分段进度条）→ 逐行 POST 自检 → 主界面。开机动画只在三个时机播放：屏幕刚被放下、存档刚被加载、以及堆芯开始坍缩（此时播的是 ERROR 301，不是开机）。其余时间一直停在实时主界面，不会自己重播。

被打掉时：挂钩留在天花板，一根电缆吊着整块屏掉下来、在半空摆动，屏上切成 NO SIGNAL 灰雪画面，30 秒后断电消失。

离线与故障：堆芯温度不到 100°C 时整屏显示「离线」而不是满屏 0；堆芯开始坍缩时立刻切到 ERROR 301「与核心失去连接」，4 秒后自动重启屏幕。

崩溃告警

坍缩期间整条标题带转红、标题改成熔毁倒计时，量表与数值同步转红。

链路指示灯

标题带右下、页脚跑马灯里都有 LINK OK / LINK SLOW / 数据中断，按最新样本的年龄变色——屏幕停住时直接告诉你停在哪一环。

事件日志不刷屏

客户端比较前后两帧，只在跨越阈值时记一条：温度等级变化、稳定度下降、结构变化、燃料装卸、坍缩开始。

数据推送与范围

服务端按采样间隔（display.displayInterval）tick 采样一次，只推给 display.displayRange 格内的玩家；范围内没人时连反射读取都跳过。需求只是软依赖——没有 NTM 也能启动并打开终端，只是屏上写「未找到堆芯」。

// 终端

右键打开，可缩放的调试窗口

左列是控制、右半边是这块屏的实时预览——预览里的像素和你站在方块前看到的是同一份。页面、电源、墙屏尺寸都服务端权威。

真正可缩放

拖右下角、滚轮、双击标题栏最大化、复位。上限就是你的游戏窗口；尺寸按方块保存在 NBT 里，客户端本地值不会被服务端下发的方块更新覆盖。

左列控制 + 底部墙屏栏

电源与四个视图（2×2 排布）加上「面板工坊」入口在左列；墙屏宽/高/复位固定在窗口底边，无论窗口拖到多小都点得到。旧版本里这组控件是顺序排下去的，窗口矮到约 300px 就被静默跳过——这才是「大小不能改」的真正原因。

右侧实时预览

跑的就是同一套画布，方块面在播开机动画时预览也在播。

服务端权威

页面、电源、墙屏尺寸都发 DFCPageMessage / DFCScreenMessage 由服务端改，再广播给附近玩家，两个人同时开终端不会各改各的。

功率计绑定

用「监控数据线」右键一个 NTM 功率计（红色电缆仪表 red_cable_gauge），再右键监控屏，即可读取每 tick / 每秒输出。

记录功率计

手持监控数据线右键红色电缆仪表。

绑定到屏

再右键监控屏，读数即出现。

摄像头接入（第 4 页）

监控摄像头放下时按你的视线定角度，之后用数据线把它接到屏上：屏幕的第 4 页在有摄像头时显示它的画面，没有时仍是面板工坊的自定义页。

记录摄像头

手持监控数据线右键摄像头，聊天栏提示「已记录摄像头坐标：CAM-…」。

绑定到屏

再右键监控屏（点任一格都行，大屏的边缘格会转给控制器）。屏幕自动翻到第 4 页。

断开

手持数据线潜行右键监控屏，画面断开，回到数据页。

摄像头必须在屏的 64 格内；绑定写在方块 NBT 里，退出重进不会断。画面每 100 ms 取一帧——它是逐条射线采样出来的，不是真的渲染，所以看得清轮廓、看不清细节。

融毁倒计时：两种算法

坍缩阶段直接取 DFC 的 explosionIn（精确到秒）；稳定阶段按两颗催化剂 damage 的实测增长速率（滑动平均）推算到 100 的时间——损伤不再增长时不显示预测，而不是拿写死的速率假装在算。

// 面板工坊

第四页留给你自己，用「当 + 若 + 则」搭规则

终端左列的「面板工坊」打开独立编辑窗口，编辑的是这块屏的一份副本，只有点「保存并应用」才真正写进世界。窗口分三区：控件设计（左列控件库 + 中列 31×19 格画布 + 右列属性表）、逻辑编排（规则列表与「当/若/则」积木）、预设库（最多 32 个命名预设）。画布与方块共用坐标，拖动重叠会被拒绝。

数据通道（条件与控件共用）

温度 熔点 稳定度 储能 输出功率 增益 催化剂损伤 结构件 燃料A 液位 燃料B 液位 熔毁倒计时 堆芯在线 坍缩中 燃料装入

前 11 个数值通道，后 3 个布尔通道。布尔通道做条件时不给比较符，直接给是 / 否——「堆芯在线 大于 0.5」这种句子不该出现在面板上。

一条规则的形状（来自 README）

当 [周期检测] 每 [20] 刻        冷却 [5] 秒    [已启用]
若 [温度] [大于] [6000]         满足全部 ▸
则 [触发报警] 等级 2 持续 10 秒
   [切换页面] → 01 核心

当（事件积木）：周期检测、数值穿越、坍缩开始、数据中断、开机时。 若（条件积木）：左通道 + 比较符（> >= < <= == !=）+ 右值（常数或另一个通道），多条条件用「满足全部 / 满足任意」连接。 则（动作积木，最多 4 个）：触发报警、显示横幅、蜂鸣提示、切换页面、记录事件、红石输出、解除报警。

触发与警报怎么生效

规则只在服务端评估，每 10 tick（0.5 秒）走一遍，所以俩人看同一块屏看到同一个报警。每条规则独立冷却（默认 5 秒）；边沿触发各记上次布尔状态、只在 0→1 触发，读档后第一遍只记录不补触发。报警是全屏叠加层（等级 2 红 / 等级 1 琥珀），红石经由 getWeakPower/getStrongPower 输出、到期自动归零。运行时（冷却、边沿记忆、红石剩余）不进 NBT。

保存、编辑与复用

「保存并应用」把整份设计打成 NBT 发服务端校验后写进方块实体；panelLayout/panelLogic 随存档持久化。底栏「复制/粘贴」能跨屏复用；「预设库」写到 config/hbmzz-panels.nbt（最多 32 个，客户端资产）。重新打开工坊即当前生效设计，「还原」丢弃本次改动。新放下的屏自带 8 个控件与 2 条示例规则，第四页一打开就能用。

// 机器控制面板

监控屏只读，这块真的能动手

贴墙装一块、右键打开、转动旋钮，几格外的 RBMK 控制棒就跟着进；把它接上警报器、防爆门、炮塔、流体储罐，逻辑也能自己动手。

它凭什么能操控别人的机器

抄了诅咒版给机器定的两条动词：机器 → 面板用 IControllable.getQueryData() 返回「名字→数值/字符串」表，面板 → 机器用 IControllable.receiveEvent(pos, ControlEvent) 收一条带命名变量的事件，getInEvents() 让机器声明自己接受哪些事件名。 反射不是编译依赖：ctrl.MachineBridge 反射找接口、缓存方法句柄，找不到就降级成「面板读不到数据」并在侧栏写明原因，不会在启动时崩。事件词表是抄来的（rbmk_ctrl_set_level、rbmk_crane_move、tank_set_mode、turret_switch、turret_set_target、siren_set_state、door_toggle、lever_toggle、spinny_light_power 等），本模组换成了扁平写法：6 个机器槽位 + 14 种控件 + 一句话规则。

面板结构

版面 32×18 格（1 格 = 8 逻辑像素，共 256×144 画布），编辑器与方块面共用同一个 CtrlPainter。控件和规则只指向槽位，整体可复制到另一台反应堆旁、只重绑槽位。上限 24 控件、6 条联动规则；绑定距离 24 格、只在服务端校验——不在范围内的槽位会被清空但保留指向它的控件。

绑定一台机器

记录机器

手持监控数据线右键机器，聊天栏提示「已记录机器坐标：RBMK 控制棒（手动）」。

接进槽位

手持数据线右键面板打开窗口；到「控件」页，A–F 某行的「绑定」按钮把它接到这个槽位。

保存并应用

点「保存并应用」才生效。赶时间可手持数据线潜行右键面板，直接塞进第一个空槽位并当场生效。

操控与规则怎么生效

每 10 tick（0.5 秒）由 CtrlEngine 走一轮——每台机器只采样一次（getQueryData 是反射调用，也是唯一贵的地方），再刷控件、跑规则。点旋钮只发「第几个 + 多少」，事件名、变量名、机器坐标都在服务端副本里，改过的客户端不能把 3 号旋钮改写成对任意方块发任意指令。规则服务端判、冷却真锁（默认 5 秒）；设计进 NBT，运行时（读数、急停锁定、冷却）不进。

终端控件：一块面板上的一台命令行

表盘适合「一直看着某个数」，不适合「现在告诉我 4 号机组的蒸汽压力是多少」。终端就是为后者加的：它不绑某一台机器，它绑这块面板——A–F 六台上绑着的机器它都能读写，当场切换目标。到「控件」页把「终端」拖到画布上、保存，回「运行」页右键它（左键也行）就开窗。

命令作用

补全与切换

Tab 按上下文给候选：第一格是命令名，use 之后是已绑定的槽位（空格位不出现），read 之后是这台机器上报的键，ev 之后是它接受的事件，再往后补出该事件的变量名（level=）。多个候选时列表浮在输入框上方，继续 Tab 循环、Shift+Tab 反向、Enter 采用并执行。

目标机器有两个入口：窗口上方 A–F 六个标签点一下，或直接打 use B。提示符会跟着变成 B>，面板上那块终端贴纸也会显示同一个目标——存档里存的是同一个字段，所以多人看到的目标一致，不是各看各的。

↑↓ 取回历史，PgUp/PgDn 翻屏，Esc 回到面板。刚放下的终端会自己指向第一个已绑定槽位；目标槽位被解绑时自动落到下一台。

为什么它不能越权

窗口只把一行文本交给服务端；机器、事件、变量都由服务端拿着自己那份面板解析。改过的客户端能打任意字，但能做的事和它手动转一个旋钮完全一样，不多一件。命令限速每秒 10 条，因为旋钮一次只发一个值，而回车可以一直按。

同一台终端，也可以装在 CE 控制台上

上面说的是模组自己的控制面板（32×18 网格、A–F 六个槽位）。从诅咒版移植过来的那块节点图控制台是另一套代码，它的编辑器里也能选到「终端」——控件列表最后一行。放一个、拖到你顺手的位置、保存，然后右键它开窗。

一台反应堆算一个部件类型

一台实用的 RBMK 不是一格方块：十几个燃料通道、一排控制棒、一两个蒸汽发生器、一个吊车控制台。以前要给它们挨个起名字绑进面板，于是窗口里是十二个标签、十二次 use、十二次 set——而操作者脑子里想的只有一个东西：「这台反应堆」。现在同一类别的机器会折进同一个槽位，一个窗口调整台堆。

两级归类，槽位边界由你来划

级别怎么判定
部件类型
family		看方块实体的类名。含 RBMK 归「RBMK 反应堆」；DFC 的零件是按功能命名的（TileEntityCoreEmitter、CoreInjector、CoreReceiver、CoreStabilizer、CoreDetonator、CoreExchanger，以及核心本身 TileEntityCore），它们全部归「DFC 反应堆」——要有这一条，一台大 DFC 才不会散成「发射器一个槽、注入器一个槽」。储罐、炮塔、警报器、门、电源盒、警示灯、控制面板各自一族。表里没有的机器类各自成族，不会被塞进别家的槽位。
槽位边界
binding		折叠只在这块终端自己绑定的零件之间进行，完全不看坐标。30 格宽的 DFC、锅炉隔了一道墙的反应堆、沿管道排开的一串储罐，都还是同一个槽位。
部件名称
part		机器类型名，例如「RBMK 控制棒（手动）」「RBMK 蒸汽发生器」。同名广播认的就是它，不是你起的联动器标签——标签的意义正是把两根控制棒区分开，而「控制棒」是它们共有的东西。

只有同一族至少 2 台时才折叠；单独一台仍用它原来的标签（A、你起的名字），所以六台互不相干的机器那块面板看起来和以前一模一样。没绑定机器的空槽也留在原位，标签条不会塌成「只剩接了线的几个」。

窗口里能看到 / 能调到什么

  • 槽位＝部件类型。标题栏写「RBMK 反应堆 · 12 部件」，提示符变成 RBMK>，use 也认这个名字。
  • read 读整组。数值键给最小–最大（四根棒 40/40/40/80 显示 40–80），文本键给不同的取值，最多三个；全部一致时就只有一个数。
  • keys / events / 变量名是并集。整台堆能读什么、能发什么，一次列全，不用来回切槽。
  • parts 是点名册。列出这个槽位里有哪些名字、各几台——也就是「我这一条命令会动到谁」。
  • 写入会显示实际台数。set level 40 之后回一行 → RBMK rbmk_ctrl_set_level level=40 ×4：四根棒动了，蒸汽发生器没动。

同名广播：什么时候触发，作用到哪

规则
触发条件本模组任何一条发往机器的道路——面板旋钮、面板规则、CE 控制台的节点图、终端——把事件交给一台已被面板绑定的机器之后。
命中条件与源机器被同一块终端绑在一起 + 同部件类型 + 同部件名称，且不是它自己。看的是绑定关系，不是坐标——离得多远都算。
作用范围只限这些同名伙伴：不跨终端（另一块面板接的反应堆不会动）、不跨部件类型。一次最多复制到 32 台，超过的部分不动。没接面板的机器永远不会被写到。这块面板要是接了两台反应堆，广播就覆盖两台——要分开，给它们各一块终端。
不触发的情形终端在部件类型槽位上发起的写入，以及节点图一次发往多个位置的广播——它们本身就是「发给整组」，再扩散一次就变成 N×N 次投递（瞬时按钮会被自己按两次）。这两条路径在写之前就把扩散关掉。
失败时先送到你指定的那台；复制给同名的部分失败，只影响伙伴，不回滚、也不改你已经发出的那一份。

为什么按「类名 + 绑定」，而不是按标签名或距离

标签是自由文本，随时能改名；要是靠命名约定（1号堆-控制棒1）分组，改个名字整个槽位就散了，而且每个人得先学会一套规矩才能用。类名是机器自己说的，不需要玩家配合。

距离看着省事，其实是在替玩家回答一个玩家没问的问题。30 格宽的 DFC 会被判成好几台，锅炉装在隔壁房间的反应堆会被拆开，而两台碰巧贴着盖的堆又会被并成一台——三种情况玩家都没法反驳。改成「这块终端绑了哪些零件」，边界就落在玩家自己按下的那一次绑定上，大机器想多宽就多宽。

代价写在明处：两台反应堆接到同一块面板上，会并成一个槽位，一条 set 两台一起动。要分开就再放一块面板或控制台，各接各的——这也正是你描述「我有两台堆」的方式。

已知限制

只有实现了 IControllable 的机器能绑；诅咒版里主要是 RBMK 控制棒 / 吊车控制台、防爆门、警报器、炮塔、流体储罐、电源盒、旋转警示灯。数据键与事件名完全取决于机器自身实现：机器没上报的键读出来是 —，机器没公布的事件发过去也不会有效果。

// 反应堆事故

RBMK 不再是一个 tick 就没了

基座模组把一台过热的堆在一个 tick 内变成废墟。行为是对的，但它是发生在你身上，不是发生给你看：上一秒还在跑，下一秒就是瓦砾。这一段把那一 tick 换成一分钟，以及一分钟之后真正会飞的东西。

什么时候开始

条件判定
温度这一台堆里任何一根柱子的 heat 超过 1000（可在 rbmk.heat 改）。1000 是刻意选的：基座模组在 maxHeat()（默认 1500）就自己动手了，取 1500 等于没有警告。
ReaSim 蒸汽要么所有存着蒸汽的柱子都顶到容量，要么蒸汽总量连续三次采样（约 2 秒）一动不动。取并集是因为容量这个数在不同整合包里不一样：基座写的是 16000，而几个常见附属把它抬到 80000 却不改字段——只看字段的话 20% 就判满。
两者都要只有热，是一台正常在跑的堆；只有蒸汽满，是一台在干活的锅炉。

然后发生什么

阶段时长在做的事
跳动1200 tick（一分钟）控制棒在通道里上下砸，棒底喷出蒸汽，落回时发出撞击声。用的就是诅咒版的跳动函数：附属在柱子上加的 leafia$damage 字段驱动它，我们只把这一个整数从 240 一路抬到 1150。
一次爆炸即刻顶盖整体离堆，初速 3.2 格/ tick，升到约 64 格，翻着跟头往下掉。整段飞行它被夹在反应堆正上方（半径 = 顶盖半宽 + 2 格），只有最后落定时才松开。
二次爆炸落地时顶盖砸回堆芯 → 氢弹尺度的一发（rbmk.lidBlastPower，默认 30）→ 带着横向分量再次掀飞（4.25 格/ tick，约 113 格）。
落定落地后 1200 tick最后落地时只炸 lidBlastPower × 0.22：第一个坑已经在，第二发满威力只会把第一个坑的证据擦掉。冒烟躺一分钟，随后碎掉消失。堆芯交给基座模组自己的熔毁。

为什么这一分钟里热量被按住了

每根柱子的 heat 在倒计时期间被钉在 maxHeat() - 50。不钉住，基座模组会在头几秒走到自己的熔毁线，倒计时还没走完堆就没了、顶盖永远不会飞——那会是一段看起来能跑、只在真堆上失效的死代码。钉子由爆炸自己拔掉，之后一切照常。

顶盖是实体，不是方块

落地时把自己放回世界，会在原地生成一根活的 RBMK 柱——一台从瓦砾里长出来、带方块实体、能继续运行的堆。所以它只是实体：带着原堆每根柱子的顶盖、按原样排布、各用各的 cover 贴图；落地只炸、只掉碎块，不改写世界。

代价同样写在明处：没有做精细的落点碰撞，顶盖按五个采样点找最高的地面，落在斜坡上会有一角悬空；落地一分钟后碎掉，不会永久留成一台「切尔诺贝利顶盖」。

像氢弹，但没有蘑菇云

蘑菇是地爆的产物：地面上的火球把尘土吸成一根柱子，柱子升到对流层顶再摊开，那是分钟级的画面。这台机器不是地爆，它是一个压力容器在露天散架；而且那片云会正好挡住整段演出唯一要展示的东西——顶盖飞上去。所以拆掉烟柱，剩下的三样照画：白闪光（几个 EXPLOSION_HUGE 加没有烟柱托底的火）、贴地扩散的尘环、喷射的水汽。

冲击波会真的打到玩家身上：相机三轴各叠两条失谐正弦波（三轴不会连成一条斜向抖动），振幅按距离平方衰减、按剩余寿命平方收敛；物品栏整条平移而不是整个 HUD——准星在那个时刻必须还能看清，玩家正在逃跑；地上再画一圈向外跑的尘环。全部由客户端从一个 37 字节的包本地生成，不从服务器一帧一帧发粒子。rbmk.shake 可关。

想看得更清楚：zd_tx

/gamerule zd_tx true。打开后，堆开始跳棒的那一刻你的视角会开始缓慢绕堆旋转，一直到掀盖爆炸为止；DFC 进入坍缩最后 5 秒时同理，绕到它炸为止。两处都在爆炸那一刻把镜头交还——留在一个坑上转圈没有意义，你要看的是那一下。

转速、半径、高度都在 cinematic.* 里（默认 0.72°/tick ≈ 25 秒一圈、18 格、+7 格）。起始角度取你当时站的方向，所以第一帧和你原来看到的是连续的。这是纯客户端演出：别的玩家看不到你的镜头在转，你的角色在他们眼里只是站着不动。

已知限制

跳动动画需要诅咒版附属（CE Addon / Leafia）。没装的时候倒计时照走、爆炸照炸，但棒子不会跳——日志里会写一行说明，而不是让你盯着一台安静了一分钟然后突然爆炸的反应堆。基座模组本身没有这个字段，也没有第二套可借用的跳动实现。

只对装好顶盖的堆有完整效果。顶盖是柱子的元数据，没有盖子的堆（或者控制棒这种自带盖子的柱子）不会被抢走任何东西：一次爆炸照炸，只是没有东西飞。

整台堆的边界由基座模组定义。相邻（上下左右，同高度）的柱子算一台堆，斜着挨在一起的不算——两侧堆在角上碰一下不会被当成一台。这条规则来自基座模组自己的熔毁扫描，不是本模组另立的规矩。

不要和 ntm-it 同时装。那个模组也在做同一套事故（自己的跳棒、自己的顶盖实体、自己的足迹爆炸，落定时还有一发强度 50 的核爆）。两个模组同时反应在一台堆上，就是两块顶盖、两次熔毁、两种爆炸数量叠在一起。进存档后的第一次世界 tick 就会在日志里点出这一行——真出事时第一个该看的就是它。

碎块里不会有带方块实体的方块。落块落地会把自己放回世界，一根 RBMK 柱子落回地面就是一台从瓦砾里长出来的活反应堆——这条规矩和「顶盖不能变方块」是同一条，2.7.1 之前碎块违反了它。

// 节点图控制台

从诅咒版整套搬过来的控制台

这块把 NTM: 诅咒版的控件、事件、变量、节点图、连线器整套搬了过来。它有 25 种控件、节点图里共 32 种节点，表达力是图灵完备级别的。

怎么放、怎么开

放下方块时底边吸附在你点的那一面：对着天花板放是吊装（板面朝下），对着地板放是平台式，对着墙放是贴墙式。 手持螺丝刀右键打开布局编辑器（NTM 的「螺丝刀」「Desh 螺丝刀」按注册名都认，主手副手都行）； 手持监控数据线右键也能打开（没装 NTM 时的替代工具）。空手右键板面上的某个控件会按下它、发一条 ctrl_press 给这个控件自己的节点图；给旁边方块供电，红石值进入面板的 redstone_input 节点。方块会输出红石：任一 redstone_output 节点算出来的值就是这块方块的弱/强充能强度，六面都算——所以它也能当可编程红石控制器用。

三层结构：控件 → 事件 → 节点图

每个控件带一张自己的电路图：物理控件（右键能按的立体模型）→ 几个有名字的 vars（isPushed / isOn / value / color）→ 接收事件（ctrl_press / tick）、发送事件（set_redstone）→ 节点图 NodeSystem（一个事件一张图，图里节点算完写回 vars）。真正动手的是节点图：放一个「红石输出」节点写的是控制台方块自己的红石，放一个「广播事件」节点把事件发给同一张面板上的别的控件。

25 种控件（按类别）

来自诅咒版本体（14）：按钮、急停按钮、防护按钮、拨动开关、旋转开关、垂直滑条、旋钮、七段数码、文字屏、方形仪表、圆形仪表、指示灯、RGB 指示灯、标签。

来自诅咒版附属 Leafia（11）：辉光数码管、大型按钮、大型拨杆开关、水平拨杆、竖直拨杆、水平仪表、竖直仪表、RBMK 阵列、图表、文字指示牌、方框标签。

RBMK 阵列 是唯一跨模组读数据的控件（反射调 CE 的 getConsoleData()）。模型与贴图一并带进来（6 个 .obj + 15 张 png），不依赖附属 jar 在不在。

节点图里有什么

分类节点

编辑器共 7 页：摆放页、连接页、节点页、事件页、变量页、安全页、控件配置页。变量分局部（控件内）与全局（整张面板共享）。事件表不是抄死的，而是运行时镜像 CE 自己的注册表，所以附属追加的事件在广播节点上也能带自己的变量。

汉化边界：协议字符串一律不翻译

翻了的是会显示给人看的字：控件名、节点名、节点分类与菜单项、按钮标题、滑条与提示文字、数学/布尔运算显示名。 没翻的是协议：控件注册名（button_push 这类标识符）、NBT 键（isPushed / nodeType / click_control）、事件词表（ctrl_press / initialize / tick）、控件变量名（value / isOn / isLit）、六个方向名（north / south…）、数据包字段名。翻哪一个都会让面板读不到数、发不出事件或读不了旧存档。节点图现在整段保持 unicode 字模开启、小字号标签按实测宽度裁剪，中文不再变成方块。

「机器控制面板」与「节点图控制台」怎么选

机器控制面板（本项目设计）机器控制台（诅咒版移植）
界面窗口里的 2D 画布世界里的立体面板 + 窗口编辑器
逻辑6 槽位 + 一句话规则每个控件一张节点图，可互相广播事件

多机联动有（槽位表）有（连接器 + 查询方块节点）

代码来源契约抄 CE，实现自写整套抄 CE，只做兼容层与汉化

两块可以同时装、互不干扰，各用自己的界面。

已知限制

OpenComputers 集成没有移植。渲染走兼容层，比 VAO 差一点。只有实现了 IControllable 的方块能被连接（CE 机器在自身包里实现同名接口，本模组用 BridgedControllable 包一层）。从机器发给面板的事件（机器→面板方向）暂时收不到，面板→机器是通的。节点图的存档与 CE 不通用，只存在本模组的方块实体里。

// 枪械 / 线圈 / 喷气背包

顺带做的几件手持装备

它们和监控屏共用同一套资源与配方体系，没有额外依赖。

制式枪械

内置三把瞬发射线枪械，全部服务端裁判：客户端只上报扳机是否按住，射速、弹匣、命中判定都在服务端算，改客户端转速也打不快。Mk.1 制式手枪（9mm，半自动精度高）、Mk.2 卡宾枪（5.56mm，全自动）、Mk.3 破门霰弹枪（12 号，半自动强散布）；弹药统一是「弹药」物品，靠 metadata 分三种口径。

Roblox 线圈

速度线圈、跳跃线圈、恢复线圈三个手持装备，无需 NTM：主手/副手持有即由服务端 PlayerTickEvent 施加对应效果（速度 / 跳跃提升 / 生命恢复），背包内不生效。效果与配方都取自 Roblox 风格设计。

喷气背包

穿戴在胸甲位，按住跳跃键向上飞，消耗耐久。耐久即燃料（满 2400，连续飞行约 6 分钟），铁砧 + 铁锭可修复；客户端把「跳跃键按下」状态发给服务端，由服务端施加 motionY 推力与火焰粒子。

// 视频广播器

让某个人屏幕当场黑掉，然后开始播片

一个方块，两个字段：播什么、播给谁。红石上升沿一到，被选中的玩家屏幕上没有任何过渡——画面直接切黑，然后开始播，播完自动恢复。

放方块、接红石

正面朝向你，红石线接到任意一面。正面小灯亮起表示正在被驱动。

右键开窗，选视频

输入包名，或者从清单里点一个——清单只列 config/hbmzz/videos/ 里真的有的东西。

填广播目标

命令方块那套选择器：@a[r=32]、@p、@a[team=red]。输入框下面会实时告诉你现在匹配到几个人。

先按「测试广播」

它走的是和红石完全相同的那条链路，所以能测通就是真能通。确认没问题再按「保存并应用」——保存本身不会触发。

只认上升沿

拉杆一直按着是一次广播，不是每秒二十次。进存档或区块重载后的第一个 tick 只记录电平、不触发——站在红石块旁边上线，不该被自己的机器糊一脸。

轮询而不是听通知

红石按 tick 结算，每 tick 问一次 isBlockPowered 与任何邻居钩子一样快，但不会漏：区块重载回来时是收不到那个「变化」的。这里漏一次，屏幕就永远不接管。

冷却兜底

两次广播至少隔 video.cooldownTicks（默认 20 tick）。漏斗钟、中继器环那种高频信号会被忽略并写进状态行，免得视频变频闪。

窗口里的两个字段

视频文件是包名，不是路径；广播目标是选择器原文。两者都存进方块 NBT，跟着存档走。窗口只编辑一份工作副本，按保存才发给服务端，服务端会重新校验一遍——包括名字白名单、长度、距离，以及（若开启）管理员权限。

目标是怎么算出来的

解析交给原版 EntitySelector，方块扮成命令等级 2 的发送者。半径和坐标以方块为原点。注意 @s 会失败：它表示「执行这条命令的实体」，方块不是实体——而且它不会被偷偷换成 @p，那样在服务器上会广播到别人屏幕去。

视频放哪、长什么样

放在客户端的 config/hbmzz/videos/ 下，两种形状都认：

alarm.zip            alarm/
  meta.json            meta.json
  f000001.jpg          f000001.jpg
  f000002.jpg          f000002.jpg
  audio.wav            audio.wav

meta.json 可以整个省掉：缺省 12 fps，帧数按目录里实际有几张图算。用一条命令把 mp4 打成包：

python tools/video/pack.py alarm.mp4 alarm --fps 12

视频要放在每一台需要观看的客户端上。服务端只发「播 alarm」这几个字，不发帧——30 秒 480p 是几十 MB，网络上传不动，这跟材质包是同一个交易。客户端没有这个文件时，它不会给你一块沉默的黑屏，而是直接报出缺的文件名和它找过的路径。

另外，ESC 默认关不掉，其它按键也一律吞掉。这是刻意的；video.allowEsc=true 可以恢复，给不想吓人的服务器留了开关。

// 红石音频 · reasim

这台播放器现在会「破」了

先说一件容易被措辞误读的事：Redstone Audio（红石音频，rsaudio）不是别人的模组。 它是本项目作者自己写的另一个独立模组，和 HBMZZ 同一个作者——以前单独发布、单独装一枚 jar， 名字叫 rsaudio-1.0.0.jar。2.9.0 做的事只是把它从「另外下一份」改成「同一枚 jar 里一起带」， 作者没变，代码也没换人写。

并进来的是整套：音频播放器、红石延迟器、结构加载器、 自动化红石计算机、六色警报灯、防核门、广播器、DMR 与 F9 两台反应堆、电梯、监控、门禁与气闸、 远程面板、列车和货运卡车，全部都在。 它仍然是一个独立模组（modid = rsaudio），只是打在同一枚 jar 里—— 因为 rsaudio: 的方块 id 已经写进了存档，改名等于让老存档里所有红石音频的机器凭空消失。

装 2.9.0 之前请把 mods/ 里独立的 rsaudio-*.jar 拿掉。 两份同时存在就是 duplicate modid，FML 会在加载阶段直接崩，而且报错文字完全指不到这件事上。 tools/deploy.py 现在会自动把它改名成 .jar.merged。

开 reasim

右键播放器 → 模式那一行最右边多了一个 REASIM 按钮 → 进去把总开关打开。 之后这台机器放出来的就不再是"干净的音乐"，而是一只装在铁皮箱里的喇叭。

顺便说明一句：reasim 是 2.9.0 新写的，独立发布的 rsaudio-1.0.0.jar 里没有这个开关。 也就是说从 rsaudio 搬过来的只有它原本那套机器，reasim 是在这个仓库里长出来的新东西； 不打开它时，播放器行为和 1.0.0 逐字节一致。

滑条范围（默认）它到底做了什么
音量0 – 200%（100%）功放增益。拧到 0 也还有一点嗡嗡声，因为底噪在增益之后。
回声0 – 100%（30%）带反馈的延迟线：延迟 90–280 ms，重复四次左右，每次更闷。
自动回声开 / 关（关）按周围空间实时算，见下。
失真0 – 100%（0%）软削波 + 位深从 16 位掉到 6 位。是"廉价 DAC"而不是"重金属"。
电流声0 – 100%（18%）50 Hz 工频哼声加二、三次谐波——铜线在磁场里的那个调子。
沙沙声0 – 100%（10%）带限白噪 + 稀疏爆裂，像接触不良的电位器。

自动回声是怎么量的

从方块中心朝六个方向各打一条最长 16 格的射线，取平均自由距离（空间感）， 再统计半径 4 格内实心方块的占比（吸收面），最后一条：头顶能看见天就把混响砍到 35%。 三件事加起来已经足够区分「砌在铁皮机房里」和「插在旷野上」。 数值每 20 tick 重新量一次，显示在滑条右边。

这不是假的。失真要波形整形，沙沙声要加噪声，回声要一条带反馈的延迟线—— 这三件事都必须拿到采样才谈得上。普通的 ISound 只给了音量和音高（一个是线性缩放， 一个是重采样），做不出来。所以 reasim 绕开了它，直接解码 ogg、跑一遍 DSP、 再把 PCM 喂进 Minecraft 自带的 paulscode 声音引擎。

代价是这部分要碰引擎的私有字段。拿不到的时候（改过声音库的客户端、非官方启动器）， reasim 会安静地退回普通播放——只是没有那些效果，音乐不会不响，日志里会写明原因。

音色是机器的，不是听的人的。参数存在方块实体上：多人服务器里所有人听到同一种破喇叭， 重进世界也还在。只有服务端能改，客户端改本地文件不会让别人的服务器上放出干净的声音。
