查表用的：控件、节点、配方、配置与构建

这页是查表页，不是教程。要学怎么放监控屏、怎么搭报警规则、怎么接机器， 去使用指南。这里只把 README 里写明的事实列成表： 控制台 25 种控件、机器控制面板 13 种控件、32 类节点、方块与物品、配方、 config/hbmzz.cfg 的全部键值，以及辅助工具和从源码构建。

// 控件

控件总表

本模组有两类能摆在面板上的控件：节点图控制台的 25 种（其中 11 种移植自 Leafia 附属），以及机器控制面板的 13 种（本项目自己设计）。面板工坊另有一套 7 种自定义控件，见下方说明。

节点图控制台 · 25 种控件

前 14 种来自 CE 本体，后 11 种来自 CE Addon（Leafia），注册名保持附属原样，已装附属的面板存档读进来不会变成 UnknownControl。

面板工坊的 7 种自定义控件

监控屏第四页「04 自定义」用的不是上面两套，而是面板工坊自带的 7 种控件：数值表、条形仪表、环形仪表、状态灯、文本标签、趋势曲线、报警横幅。它们的显示内容与报警规则由「当 + 若 + 则」积木定义，详细用法与通道清单见 使用指南 · 面板工坊。

// 节点图

节点图里有什么

节点图是控制台「每个控件一张电路图」的执行层：一个事件一张图，图里的节点算完把结果写回控件的 vars。当前共有 32 种节点，按下面 8 类组织。

分类 节点
输入 事件数据、读取变量、查询方块、红石输入、批量查询、图表区间
输出 广播事件、取消当前事件、设置变量、红石输出、播放声音、写入图表
数学 加减乘除、取余、幂、对数、指数、平方根、绝对值、比较、限幅、最大最小、取整（20 种运算，一个节点切着用）
布尔 AND / OR / NOT / XOR / NAND / NOR / XNOR，外加脉冲、SR 锁存
逻辑 函数（自定义表达式）、缓冲器（延迟一拍）、条件（if）
数据包 读取数据包、写入数据包（复合类型打包 / 拆包）
文本 文本拼接、取子串、格式化、数值缩写
实用 缓存、时钟、随机整数、随机小数、汇总、文本转数字

广播事件（输出）

广播节点把事件交给 ControlEventSystem；本表只有控制台自己（只登记 tick），查不到就走 compat/CPMachines，把 CE 机器包成 IControllable 由 ctrl/MachineBridge 反射发出上游自己的 ControlEvent。tools/linkercheck 里有一条检查专门盯这条链路。

数学与函数（逻辑）

数学类用一个节点切出 20 种运算（加减乘除、取余、幂、对数、指数、平方根、绝对值、比较、限幅、最大最小、取整）。函数节点用诅咒版表达式解析器，可写 a*2+sin(b) 这样的式子。

变量（输入 / 输出）

变量分局部（只在这个控件里）与全局（整张面板共享）两栏；读取变量 / 设置变量 都带全局 / 局部下拉。控件与条件共用的通道不在这里，那是监控屏面板工坊的概念。

红石输入 / 红石输出

红石输入能选六个面 + 六种读法（强度、弱充能值、强充能值、是否通电、是否弱充能、是否强充能）；红石输出能选六个面 + 弱 / 强充能，直接作为控制台方块的充能强度，六面都算。

布尔逻辑门（布尔）

AND / OR / NOT / XOR / NAND / NOR / XNOR 六个基础门，外加脉冲、SR 锁存。条件（if）单独在逻辑类，做分支判断。

条件与缓冲器（逻辑）

条件节点做分支（if）；缓冲器延迟一拍，用于把上游结果往后挪一个周期再参与计算。

// 方块与物品

方块与物品

README 的「方块与物品」一节描述了这些方块 / 物品的行为。注册名 README 未单列，故本表不填（以 — 表示）。

名称 注册名 用途
DFC 监控屏 — 吊装式工业终端。方块本体不渲染（INVISIBLE + 空模型），整机由 TESR 画：外壳、前框、吊架、屏幕；倾角 0–60 度五档，壁挂或吊装。
屏幕占位格 — 面板除控制器外的格子，没有方块实体，只提供碰撞与「拆一格带走整屏」的入口。
机器控制面板 — 3/16 格厚的贴墙铁板，正面是屏幕 + 三色灯 + 旋钮拨杆贴图；没有 TESR，真面板放进右键打开的窗口里。
机器控制台 — 诅咒版控制台整体移植。方块本体不渲染（ENTITYBLOCK_ANIMATED + 空模型），整个板子连同控件由 TESR 画出，控件是真立体模型。
视频广播器 video_broadcaster 普通满方块，正面一块小屏 + 状态灯。红石上升沿触发，把选择器选中的玩家屏幕换成一段视频。见 使用指南 · 视频广播器。
监控数据线 — 一个物品干两件事：记录 DFC 核心 / 功率计并绑定到监控屏；记录可控机器，并当控制台的配置工具用。

// 辅助工具

辅助工具（tools/）

仓库里几个不进游戏就能跑的验证脚本，README 明确写到的三个如下。

脚本 作用 怎么跑
tools/PreviewMain.java 不进游戏把各页面渲染成 PNG：直接跑真正的 DfcScreen / TerminalCanvas，只跳过纹理上传，出图与方块面像素一致。 
javac -encoding UTF-8 -cp "build/classes/java/main;<lwjgl.jar>" -d build/classes/java/main src/main/java/com/hbmzz/client/screen/*.java
javac -encoding UTF-8 -cp "build/classes/java/main;<lwjgl.jar>" -d tmp/pv tools/PreviewMain.java
java -Djava.awt.headless=true -cp "tmp/pv;build/classes/java/main;<lwjgl.jar>" com.hbmzz.tools.PreviewMain dist
tools/parity/run.sh 核对「诅咒版控制台是不是完整抄过来了」：解 jar → 反编译 → 归一化包名与 SRG 名 → 与 com/hbmzz/cecp 逐行 diff，同时报类覆盖与方法覆盖。 
./tools/parity/run.sh "/c/.../mods/[HBM的核科技社区版] NTM-CE-1.12.2-2.5.0.5.jar"
tools/linkercheck/run.sh 离线验证机器导入链路（LinkerImport / 监控数据线的 NBT / 反射探测上游接口），不启动游戏。输出 11 项 PASS。 
./tools/linkercheck/run.sh "<NTM-CE.jar>"
tools/videocheck/run.sh 离线验证视频包能不能被 VideoClip 读出来，并跑一遍名字白名单（../x、a/b 必须被拒）。不碰方块、不碰网络。输出 26 项 PASS。 
./tools/videocheck/run.sh
tools/regcheck/check.py 静态核对「声明了但没注册」：Block / Item 是否进了对应注册表、每个可放置方块有没有物品、每个 extends TileEntity 的类有没有注册名。2.3.1 修的「广播器没有物品」「摄像头放下就崩」正是这类漏项。纯文本分析，不启动 JVM。 
python tools/regcheck/check.py
// 构建

从源码构建

前置取自 build.gradle 与 README：JDK 8、Gradle 4.10.3（ForgeGradle 2.3），MC 1.12.2 / Forge 14.23.5.2847，mappings snapshot_20171003。仓库自带 wrapper。

命令序列

# 用仓库自带的 wrapper 构建
gradlew build

# 产物（版本号取自 build.gradle 的 version）
build/libs/hbmzz-<版本>.jar

当前版本为 x.y.z，产物即 build/libs/hbmzz-x.y.z.jar。Windows 下用 cmd / PowerShell 跑 gradlew.bat。

JDK 必须是 8

本模组目标字节码是 Java 8（sourceCompatibility = targetCompatibility = '1.8'），且诅咒版移植代码做了 Java 9+ 语法降级。用 JDK 9+ 编译可能在 instanceof 模式匹配、switch 表达式、var、Optional.isEmpty()、String.isBlank() 这类地方出问题。请固定使用 JDK 8。

已知问题：wrapper 在 Git Bash / MSYS 下报 GradleWrapperMain

在 Git Bash / MSYS 环境里直接 ./gradlew 可能报 Could not find or load main class org.gradle.wrapper.GradleWrapperMain。可改用下面这行直接驱动 wrapper jar，效果相同：

java -cp gradle/wrapper/gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain build

另：若 wrapper 的 gradle-wrapper.jar 丢了，不要对 2.3-SNAPSHOT 联网重新解析（会拉到给新 Gradle 编的 ForgeGradle，配置阶段就炸），改用本地缓存的 ~/.gradle/wrapper/dists/gradle-4.10.3-bin/*/gradle-4.10.3/bin/gradle.bat build，卡在 services.gradle.org 时加 --offline。

// 已知限制

已知限制与外部崩溃

来自 README 的「已知限制」与「已知的外部崩溃（不是本模组引起）」两节。

类别 限制
墙屏结构 墙屏是同一台设备的渲染跨度，不是独立的多方块结构：其余格子仍是各自的监视器方块，只靠覆盖判定跳过重复绘制。拆掉控制器（左上角那一格）时整面屏一起消失；拆中间某一格只会留下一个缺口，不会连带拆掉邻居。
终端窗口 终端窗口尺寸是客户端本地偏好，不随存档同步给其他玩家。
融毁倒计时 稳定阶段的倒计时是预测：基于实测的催化剂损伤增速，DFC 在无干扰器时仍可能瞬间爆炸。
功率计 功率计必须手动绑定；终端不会自动搜索功率计。
枪械判定 枪械是瞬发射线判定，没有子弹实体、弹道下坠和穿透；伤害不区分部位。
枪械交互 右键对着可交互方块（箱子、工作台等）时，开火会和方块交互同时发生，枪械没有做「交互优先级」判定。
字体 首次打开屏幕时 AWT 需要探测系统字体，极少数精简 JRE 环境可能没有中文字体，此时中文会退化成方框（logs/latest.log 里有一行字体探测结果）。

已知的外部崩溃（不是本模组引起）

在装了 NTM 诅咒版（NTM_Cursed_Edition）的整合包里，DFC 核心附近偶发 ConcurrentModificationException，栈是 com.hbm.tileentity.machine.TileEntityCore.tickClient，里面没有一行 com.hbmzz。原因是诅咒版把 dfcShocks 这个 List 通过 DFCShockPacket 在 netty 线程里 add，而 tickClient 同时在主线程 for 遍历它。本模组对此无能为力，只能把自己的开销压到最低：把 display.liveScreen 设成 false 可以完全关掉方块面渲染，用于确认崩溃是否与本模组无关。
